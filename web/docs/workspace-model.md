# 工作区交互模型

工作区里有两种东西：**画布**（Excalidraw 场景 + 它的评论）和**会话**（用户选定的 Pi / Claude Code / Codex 的一个原生会话，挂在某块画布上，见 [Agent 会话](agent-sessions.md)）。它们以 tab 的形式放进分组，分组组成分屏。本文定义它们的生命周期、新建入口、关联表达和指示方式；实现见 `src/workspace/model.ts`（纯函数）、`src/workspace/Workspace.tsx`（渲染与拖动）、`src/app/App.tsx`（接线与持久化）。

## 1. 三层状态：存在、打开、当前

| 状态 | 含义 | 在哪里看到 |
|---|---|---|
| 存在 | 属于这个工作区，数据（场景、评论、会话记录）都在 | 「所有画布」列表 |
| 打开 | 在某个分组里有 tab | 分组的 tab 栏 |
| 当前 | 分组里正在显示的 tab；聚焦分组里的当前 tab 就是键盘和 Dock 作用的对象 | tab 下方的指示条；聚焦分组的指示条是紫色 |

- **关闭**只把 tab 收起：打开 → 存在。数据一律保留，刷新后仍在「所有画布」里，点一下就重新打开。
- **删除**是另一个操作：存在 → 没有。只在「所有画布」列表里（或 tab 右键「删除…」跳到列表里那一行）做，页面内确认，删除后底部出现「撤销」，可撤销最近一次删除。
- 至少保留一块画布：最后一块画布不能删除，但可以关闭。
- **草稿会话**：新建的会话在选定 agent 之前是草稿，只在页面内存里，不写入 `.agora/`（`workspace.json` 里没有它的条目和 tab，`sessions/` 下没有它的记录）。选定 agent 的那一刻起才保存。关闭草稿就是丢弃它：不进「所有画布」，不留任何记录；刷新页面时未选 agent 的草稿也随之消失。只有本页新建的会话才可能是草稿——从项目里载入的会话，哪怕从未选过 agent，也照常保留、照常列出，不会被自动清理。

对照：浏览器关 tab 就是丢掉页面（靠「最近关闭」补救）；VS Code 关 editor 不删文件，文件还在资源管理器里。画布和会话是用户的产出，更像文件，所以取 VS Code 的语义：关闭不删，删除单独做。「所有画布」列表相当于资源管理器。

## 2. 两种 tab

| | 画布 | 会话 |
|---|---|---|
| 默认名 | 「未命名画布 N」 | 未选 agent：「新会话」；选定后：agent 名（「Claude Code」），首轮消息后「Claude Code · 加 Kafka」 |
| 编号 | 画布之间独立计数，取当前存在的画布里未被占用的最小 N | 不编号；只有自动名字撞车时才加后缀：「Claude Code · 加 Kafka 2」 |
| tab 上的标记 | 方形小标 | 选定后是 agent 头像；草稿是圆形小标 |
| 改名 | 双击 tab 或右键「重命名」 | 同左；改成空白即恢复自动名字 |

- 画布不共用计数器，关掉或删掉「未命名画布 2」后，下一块新画布就是「未命名画布 2」，不会跳到 7。
- 改过名的画布不占编号。
- **会话的自动名字**（`sessionTitles`、`topicOf`，`src/workspace/model.ts`）：用户改过名就用用户的名字；否则是 agent 名，拿到首条用户消息后加上主题。主题不调用模型，规则是：去掉 Agora 附加的内容（`[[agora]]` 页脚、「（引用的画布元素…）/（当前选区…）」附注；评论交接取第一条评论的正文），取第一行非空文字，去掉 Markdown 标记和「请 / 帮我 / 麻烦 / 能不能 / 可以 / please / can you」这类开头和句末标点，最多 18 列（中文一个字算 2 列），超出用「…」。主题只取一次，存进 `workspace.json` 的会话条目（`topic`）。自动名字重复时，后出现的加「 2」「 3」；用户起的名字不改。
- 旧版本存的「会话 N」视为自动名字，载入时换成上面的规则；只改显示名，会话本身和记录不动。
- 首次打开工作区（项目里一块画布都没有，服务端 `snapshot.empty`）时，自动建一块「示例架构图」和它的会话；之后新建的画布一律空白。想要示例，用「从示例新建」。workspace.json 丢了但画布还在时不算首次：按磁盘上的画布恢复列表（[项目存储](project-storage.md)）。
- 删除画布会立即结束它的分享（访客链接失效）；删除会话会关掉它的终端 pane，原生对话留在 CLI 自己的日志里。

## 3. 会话和画布的关联

每个会话属于一块画布（会话里的 agent 默认改的就是这块）。表达方式：

- 会话 tab 标题是会话自己的名字，关联画布名以浅色小字跟在后面：`Claude Code · 加 Kafka  示例架构图`。名字归会话，关联是附加信息，改画布名时会话 tab 跟着变，但不会把会话名顶掉。原来的「Pi Master · 架构图 1」把 agent 名当标题，每个会话都叫 Pi Master，看不出区别。
- 「所有画布」列表里，会话缩进挂在所属画布下面；画布删掉后，它的会话挂在「未关联画布」下，记录保留，可以在会话里改关联。
- 画布关闭时，关联会话照常使用；在会话里发消息时如果画布没打开，会先在画布所在分组把它打开，再执行。
- 画布评论「交给 Agent」交给这块画布上最近活动的会话（没有已选 agent 的会话时先让用户选），agent 的答复贴回线程，改图卡片同时出现在会话里。规则见 [Agent 会话 §1](agent-sessions.md#1-会话模型)。

## 4. 新建入口

| 入口 | 新建什么 | 放到哪里 |
|---|---|---|
| 顶栏「新建画布」 | 空白画布 | 最近使用的画布所在分组（没有就放聚焦分组） |
| 顶栏「新建会话」 | 会话，关联当前画布 | 不含该画布的分组（和画布并排，而不是把画布挤掉）；没有就放聚焦分组 |
| 分组里的「+」 | 按分组类型：全是画布 → 空白画布；全是会话 → 会话（关联最近使用的画布）；混合或空分组 → 弹小菜单：新建画布 / 新建会话 / 从示例新建 | 这个分组 |
| 双击 tab 栏空白处 | 同该分组的「+」 | 这个分组 |
| 「所有画布」列表底部 | 新建空白画布 / 从示例新建 | 同顶栏「新建画布」 |

顶栏按钮的语义是「我要一个 X」，位置由系统按关联关系选；分组里的「+」的语义是「在这里再来一个同类的」。这和浏览器（新 tab 开在当前窗口）、VS Code（编辑器组里的新文件留在该组）一致。原型里会话组的「+」新建的是画布，就是违反了「同类」这条。

新画布创建后直接进入改名状态，回车确认，Esc 保留默认名。

## 5. 分组、关闭与拖动

- 关闭分组里最后一个 tab：分组消失，相邻分组占掉空间（VS Code 默认行为）。
- 如果它是唯一的分组：保留一个空分组，内容区显示「没有打开的画布或会话」和新建 / 打开列表的入口，不自动塞一块新画布。
- 拖 tab 到别的分组 tab 栏：移入该组；拖到分组边缘：分出新分组；拖走分组里最后一个 tab：原分组消失。
- 拖动、分屏、排列预设只改变布局，不改变存在/打开状态；排列预设只处理打开的 tab。
- 关闭当前 tab 后，同组左侧相邻的 tab 成为当前；聚焦转到那个 tab。

## 6. 当前 tab 与聚焦分组的指示

分组平铺在同一张底色上，之间只隔一条 1px 发丝线（设计规范 D13），tab 栏与内容区同底色，所以「连成一体」不再能指示当前 tab，改用底部指示条：

- 当前 tab：文字为正文色，下方 2px 指示条；切换时指示条在组内滑动。非当前 tab 文字为次级色，悬停时浮出浅底。
- 聚焦分组：当前 tab 的指示条和种类小标用强调紫；非聚焦分组的指示条是中性灰。只有一个分组时也这样画，不需要额外区分。
- 分组之间的发丝线就是拖动分隔条：悬停或拖动时原位显示 2px 紫线，命中区 8px。
- 改名：tab 原位变成同尺寸输入框，浅灰底，选区为浅紫，没有描边或光环。

## 7. 持久化

存在项目的 `.agora/` 里，由该项目的本地服务读写，格式见[项目存储](project-storage.md)：`workspace.json` 保存全部画布和会话（含已关闭，草稿会话除外，见 §1）、分屏树、聚焦项、格式版本 `v: 2`；`canvases/<id>.excalidraw` 与 `threads/<id>.json` 保存场景与评论，删除画布时一并删除，撤销时写回；`sessions/<id>.jsonl` 保存会话记录，删除会话时删文件，撤销时整份写回。撤销只在当前页面有效，刷新后删除即为最终结果。

## 8. 取舍

- 不做「最近关闭」栈（浏览器的 ⌘⇧T）：关闭本身不丢数据，列表足够找回，少一个概念。
- 不做回收站：删除已经有页面内确认 + 一次撤销，回收站会让「删除」和「关闭」再次难以区分。
- 分组没有显式类型设置：类型由里面的 tab 推出来，拖动后自然变化，用户不需要维护它。
