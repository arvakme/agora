# 多 Agent 同时改一个项目

一个会话锁定一个 agent，但一个项目可以同时开好几个会话：Claude Code 在改后端，Codex 在改前端，Pi 在写文档，都在同一个工作目录里。本文说明这种情况下 Agora 显示什么、提醒什么、不做什么。

实现：`web/src/multi/pointers.ts`（纯函数：活跃会话、每会话指针、同节点并排、冲突检测），`web/src/multi/writes.ts`（所有会话的写入折一次，指针、冲突、过时、工位视图共用），`web/src/pointer/PointerLayer.tsx`（画布上的多指针、冲突标记、边缘指示），`web/src/multi/ConflictNotice.tsx`（会话面板里的提示），`web/src/canvas/chrome.ts`（叠加层避开画布界面）。

## 1. 场景

| 场景 | 以前 | 现在 |
|---|---|---|
| 两个会话都在改，想知道各自在哪 | 只有一个指针，跟随最后聚焦的会话 | 每个活跃会话一个指针，用它的 agent 头像；聚焦的那个带靶心图标、排在前面 |
| 两个会话改到同一个模块 | 指针互相覆盖 | 同一节点一个描边，标签并排：`Claude Code · service.py`、`Codex · repo.py` |
| 两个会话几分钟内改了同一个文件 | 看不出来 | 节点标签行末尾「可能冲突」，两个会话面板顶部各一条提示，说明是谁和谁、哪个文件 |
| 改了图外的文件 | 一个列表 | 「在架构图之外」按会话分组 |
| 节点被面板挡住或滚出视野 | 描边画在面板上面 | 不画描边，最近的空闲边缘放一个「头像 + 箭头」，点它把节点滚回视野 |

## 2. 指针

- **哪些会话有指针**：正在运行的，30 分钟内有动静的（`ACTIVE_MS`），以及最后聚焦的那个。其余会话的历史不显示，免得画布上堆满旧指针。
- **一个会话一个指针**：落在这个会话最近一次能映射到节点的写入上，规则和[进度指针](progress-pointer.md)相同（最具体的 glob 胜出，子图的路径汇总到父节点，见[嵌套画布](nested-canvas.md) §5）。
- **同一节点**：一个描边；标签按「聚焦的会话在前，其余按最近写入」排成一行，量过宽度后整体放在描边外第一个不压东西的一侧（避开图上的文字图标、评论钉、其他指针标签和画布界面）。
- **名字**：用 agent 名；同一种 agent 有两个活跃会话时用会话名（「Claude Code · 加 Kafka」）区分。
- **颜色**：仍然只有一种强调紫（设计规范），会话靠头像区分，不给每个 agent 发一种颜色。
- **层级**：指针、工位小人、子图标记都画在 Excalidraw 界面（样式面板、工具栏、素材库按钮、缩放撤销、底部栏、菜单）之下、场景之上，并按这些面板和我们自己的浮层（dock、评论卡、节点菜单）挖洞裁剪，既不遮挡也不抢点击。目标节点中心被挡住或不在视野里时改用边缘指示。

## 3. 冲突检测：提醒，不阻止

**判定**（`conflicts`）：两个不同会话的两次写入，间隔不超过 10 分钟（`CONFLICT_WINDOW_MS`），并且

- 写的是**同一个文件**（包括图外文件），或
- 写的是**同一个节点**下的不同文件（按当前画布的有效路径映射）。

同一对会话、同一个文件 / 节点只算一条，取最近的一次；最近那次写入超过 60 分钟（`CONFLICT_SHOW_MS`）后不再显示。回放时只看回放时刻之前的写入。

**显示**：

- 画布：该节点指针标签行末尾一个「● 可能冲突」（提示色小点 + 文字），点开列出每一条：「Claude Code 与 Codex 在 1 分钟内都改了 server/orders/service.py」，每个写入带「第 N 轮」跳到对应会话的轨迹。图外文件的冲突在「在架构图之外」的那一行上打小点。
- 会话面板：顶部一条提示，带「看 Codex」直接切到对方会话；「知道了」收起，有新冲突再出现。

**为什么不阻止**：两个 CLI 各自在自己的进程里写文件，Agora 不在它们的写入路径上，拦不住；强行在发消息时排队又会把「一起干活」变成串行。能做的是尽早让人看到，由人决定谁来合。真正的隔离见下一节。

**局限**：只认日志里的编辑工具写入（和进度指针一样，`sed -i`、`cat >` 不算）；同一文件不同位置的修改也会报（不做 diff 级判断）；10 分钟窗口是经验值。

## 4. 隔离模式（设计，本轮未实现）

**想法**：会话创建时可选「隔离」：Agora 为它建一个 git worktree（`.agora/run/worktrees/<会话 id>`，分支 `agora/<会话 id>`，从当前 HEAD 拉出），这个会话的无头续接和终端都在那个目录里跑。两个 agent 不再写同一份文件，冲突只在合并时出现。

**指针照样映射回同一张图**：会话日志里的路径相对于它自己的 worktree 根目录，而 worktree 和主目录的相对路径一致，所以 `transcript.py` 的 `State.root` 设成 worktree 根就能得到和主目录一样的 `server/orders/service.py`，节点匹配、嵌套汇总、工位视图都不用改。画布、评论、会话记录仍在主目录的 `.agora/` 里（`AGORA_PROJECT` 指向主目录），`agora canvas` 照常工作。

**要改的地方**：`agents.py` 的无头与交互式命令的 cwd；Codex 认领 rollout 时按 worktree 目录比对；skill 链接装进 worktree（`.git/info/exclude` 是共用的）；指针标签上标出「隔离」；会话面板加「合并回主分支」（显示 `git diff main...agora/<id>` 的文件列表，一键 `git merge --no-ff`，有冲突时列出冲突文件交给用户或 agent 处理）。

**为什么本轮不做**：

1. **生命周期规则还没定**：worktree 什么时候删？删除会话时有未合并的改动怎么办？撤销删除时要不要恢复 worktree？这些正是另一条线在分析的「关闭 / 删除 / 找回 / 仓库移动」语义，现在自定一套会和它冲突（本轮要求沿用现有规则，不定新语义）。
2. **合并界面是新功能**：列 diff、处理冲突、决定合并顺序，工作量比指针本身大，而且要先和用户确认交互。
3. **和现有「在终端打开」「无头续接」的交接要重测**：三个 CLI 各自按 cwd 定位会话日志（Claude 按目录分文件夹，Pi 按 `--<cwd>--`），虽然 Agora 按 id glob 找日志，但每个 CLI 的首次信任提示、skill 发现都要在新目录再走一遍实测。

推荐下一轮：生命周期规则落定后，先做「创建时可选隔离 + 在 worktree 里跑 + 指针映射 + 只读的 diff 列表」，合并先让用户在终端里自己做；合并界面再单独一轮。

## 5. 取舍

- **30 分钟活跃窗口**而不是「所有会话」：项目里旧会话会越积越多，画布只该显示现在的工作；想看历史用工位视图的时间线回放。
- **按节点合并描边**而不是每个会话一个描边：两个描边叠在同一个节点上看不清，也不美观；并排的标签已经说明是谁。
- **冲突放在标签行里**：不再单独找地方放，也就不会压住节点或箭头；节点当前没有指针时，冲突标记放在节点左上角上方。
