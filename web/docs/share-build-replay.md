# 施工回放：看这张图是怎么从 0 到 1 搭起来的，小人也在

用户的话：「访客可以看到全过程。增加施工日志。访客没有小人，只可以评论，只能看到我的工作过程以及架构图的搭建流程，从 0 到 1 的过程，评论现在不限制必须绑定元素」；「访客版设置开关我来决定」。

拿到分享链接的人（作者在分享窗口里勾了「让访客看搭建过程」才有）点「看搭建过程」：画布从起始的样子开始，一件一件长出来；谁做的，它的小人就走到那里去画；作者自己动手改的是「作者」这个小人；画了又删的想法也演出来；气泡用人话说做了什么；空闲时间压掉，有播放、暂停、倍速和进度条。**访客本人不在图上，没有小人**，只能评论——对某个元素，或对整张图（可以顺带记下看到回放的哪一刻）。

**状态**：全部已做。代码：`server/canvas/buildlog.py`（施工日志的写）、`server/canvas/build_log.py`（日志和会话 → 时间线）、`GET /api/project/build`、`GET /api/guest/build`（`share_gateway.py`）、`server/canvas/share.py`（`buildReplay`、分享包里的日志）、`web/src/buildreplay/`（回放）、`web/src/comments/WholeCanvas.tsx`（整张图评论）；测试 `tests/test_buildlog.py`、`tests/test_build_log.py`、`tests/test_share_build.py`、`web/src/buildreplay/*.test.ts`、`web/src/comments/visibility.test.ts`。

## 1. 谁看到什么

| | 作者（本机） | 访客（分享链接） |
|---|---|---|
| 入口 | ⋯ 菜单「看这张图是怎么搭起来的」，或 `?buildreplay=<画布>` | 顶栏「看搭建过程」，**只有作者创建分享时勾了「让访客看搭建过程」才有**；没勾，访客页和以前完全一样，服务端也不给数据（`/api/guest/build` 是 403） |
| 内容 | 这张画布和它下面的子画布，从起始画面到现在的全过程 | 同一份：分享的那张和它下面的子画布，**全过程**，包括画了又删、改了又改的（作者的选择：「访客可以看到全过程」） |
| 小人 | 每个 agent 一个（头是它的标志）；作者自己动手改的是头里写着「你」的中性小人 | 同样的小人；作者动手的那个叫「作者」（头里写「作」）。**访客自己没有小人** |
| 时间 | 作者的钟 | 从第一步起算，不给作者几点在工作 |
| 评论 | 钉在元素上，或对整张图；在回放里评论会记下那一刻 | 同样；访客的评论仍走网关的白名单和大小限制 |

回放页：

- **画布**：从起始画面开始（没有起始画面就是空白），每件事做完，那一批元素出现在画布上；镜头跟着小人，放得下整张图就整张图（缩放 55%–100%）。
- **小人**：走到要画的节点上再画：同一张图里沿画好的线走桥、爬梯，没有线相连就搭脚手架（和工位视图完全一样）。
- **子图**：一个节点被展开成子图，之后在子图里画东西时，小人走到那个节点，顺梯子下去，画面交叉淡变到子图，小人从入口上方顺梯子爬下来接着画；画完回到上一层是反过来。一次只看到小人所在的那一张。
- **气泡**：一句人话，用画布上自己的字写：「加了节点「controlplane（Go）」」「连了 nginx 边缘 → webapp、controlplane」「把「webapp」展开成子图」「把「后端」改名为「API 服务」」「挪了「前端」」「删掉了「缓存（试试）」」。不说文件、命令、路径。
- **控制**：播放 / 暂停 / 重看；倍速 1× 2× 4× 8× 16×，默认取「大约一分半看完」的那一档；进度条可拖，右侧是「做了什么」的列表（当前一条高亮，点一条从那里播）；Esc 关闭。空闲时间不存在：一件事接着一件事，时间轴是回放自己的钟（`plan.ts`），不是作者的墙上时间。
- **评论这一刻**：右侧列表下方一个输入框，发出去是一条**对整张图的评论**，记下正在看的那一步（`moment.step`）。之后在评论列表里，这条评论带「回放第 N 步」，点它打开回放停在那一步。
- **精简 / 逐步**：底栏一个开关，默认「精简」（§13）：小人在一片区域只走一次，够得着的就站着画，线从起点节点拉出去，太远的直接换位置；「逐步」是每一件事都走到那里再画的完整走法。切换时停在正在看的那一步。
- **减少动效**：小人不走，位置变化淡出淡入（和工位视图一致）。

**取舍：十秒内画了又删的**，和其他十秒内的手动改动一样，合成一步（画出来又删掉 = 什么也没有），因为它更像是手滑；停了十秒以上再删的想法才是「画了又删」，会演出来。

## 2. 数据从哪里来

**从现在起是施工日志（§3）**：画布每次保存，服务端往 `.agora/buildlog/<画布>.jsonl` 追加一条记录，只含元素的增、删、改，带时间和是谁做的。回放的历史就是这份日志顺着放一遍。

**老项目（没有日志的）**：从现有数据还原能还原的部分，此后用日志。日志的第一条记录带 `legacy: true`（「日志开始时这张画布已经在那里了」）；在这之前的历史由 `build_log.py` 从会话记录里派生，之后是日志。派生的做法：

- `sessions/<会话>.jsonl` 记着页面替 agent 做的每一次改图（`agora canvas apply | link | child`）：一个 turn（何时、哪个会话、哪张画布、状态）加一个 batch：这次碰过的元素**改之前**的完整内容（`null` = 之前不存在）和改之后的版本号。从当前画布往回把每一批的「改前」放回去，就得到每一批之前的画布；再往前推，得到每一批做出来的元素。
- 没被任何批碰过、`updated` 早于第一批的元素 = 起始画面（示例图就是）；晚于第一批的 = 人后来画的（一步「你画了…」）。
- 一个元素的「下一批改前版本」比「上一批改后版本」新，或当前版本比最后一批的改后版本新 = 两批之间有人改过它（一步「你调整了…」，看不到改前的样子）。
- 边界：只记页面替 agent 落笔的部分（页面没开、agent 直接写文件的改动没有）；会话文件不在了（`git clean`、克隆到别处）这部分就没有——这正是日志要做成提交进项目的原因。

agora-fresh 的实测（拷贝，只读）：24 个 agent 改图 turn，全在 3 张画布，共 195 个元素，其中 168 个能逐个落到某一个批里；起始画面 27 个元素。第一次保存之后日志接上：人手画的矩形是「作者/你」的一步，画了又删也在。

**其他来源不用**：本地版本历史（稀疏，不知道谁改的）、每日备份（只到 7 天）、项目 git（粒度太粗）、agent 的原生日志（含命令、路径、密钥，不应进入任何分享）。

## 3. 施工日志

`.agora/buildlog/<画布 id>.jsonl`，一行一条 JSON，**提交进 git**（和画布、评论同等地位：别人克隆项目就能看回放；不在 `.gitignore` 里，`agora init` 生成的 `.gitignore` 不写它）。

```
{"t": 1790682084239, "base": [元素…], "legacy": true}        第一行：日志开始时这张画布的样子
{"t": 1790682090001, "g": [{"by": {"kind": "agent", "agent": "claude"}, "put": [元素…], "del": ["id"…]},
                           {"by": {"kind": "you"}, "put": [元素…]}]}   之后每次保存一行
```

- **第一行 `base`**：画布文件第一次被写就是它的起始画面（示例图、导入的画布、空白页）；日志开始时画布文件已经在的（老项目）带 `legacy: true`。
- **`put`**：这次保存里新出现或变了的元素（整个元素，几百字节）；删掉的元素是 `isDeleted: true` 的一次 `put`，从文件里消失的写进 `del`。**只有 `updated`、`version`、`versionNonce`、`index` 变了不算改动**。
- **`by`**：谁做的。`{"kind": "agent", "agent": "claude"}` 或 `{"kind": "you"}`（作者）。agent 的改动靠「元素 id + 版本号」认：agent 的批（`sessions/*.jsonl` 里的 batch）记着它改完后每个元素的版本，保存里版本对得上的就是它的；文字元素跟着它所在的形状。批通常比保存晚到一点点，所以先记成「你」，批到了（会话追加记录时）再把匹配的元素挪到 agent 名下（`buildlog.attribute_batches`）；读的时候还会用会话再核一遍。剩下的就是作者的。
- **绝不进日志**：会话内容、请求原文、agent 的回复、命令、令牌；元素的 `customData`（代码路径、素材库标记、动画数据）——只留指向子画布的 `childCanvas`。所以「关联代码」这类改动不会出现在日志里（对回放没有可看的变化）。
- **合并**：同一个人 1 秒内的连续保存合成一条（拖一个节点不会写几十条）；同一次保存里有几个人的改动就是 `g` 里几个组。
- **体积**：历史部分（起始画面之外）超过 1 MB 时，把最近 400 条之外的旧记录压缩：先把同一个人 1 分钟内的相邻记录合并，还大就 10 分钟，还大就折进起始画面（`base`，日志加 `folded: true`，更早的过程就没有了）。最近 400 条永远原样。压缩不改变「画布现在是什么样」（`state_of` 前后一致），只丢中间态。
- **失败**：写日志是保存画布的副作用，出任何错都吞掉，绝不让保存失败。日志坏了一行（半行、手改）跳过那一行继续读。
- **跟着画布走**：进回收站、恢复都带着日志；分享包带日志（§7）。

## 4. 时间线的格式

`GET /api/project/build?canvas=<id>`（主人，本机）和 `GET /api/guest/build`（访客，§5）给同一种 JSON：`build_log.build_timeline(store, root, relative=False)`，访客版 `relative=True`（时间从第一步起算）。

```json
{
  "format": "agora-build-timeline", "version": 1, "root": "c1",
  "canvases": { "c1": {"title": "总架构", "parent": null},
                "c-web": {"title": "webapp", "parent": {"canvas": "c1", "node": "o-web"}} },
  "start":  { "c1": [元素…], "c-web": [] },
  "steps": [
    { "i": 0, "at": 1790682084239, "until": 1790682084252, "canvas": "c1",
      "actor": {"kind": "agent", "agent": "claude", "name": "Claude Code"}   /  {"kind": "you"},
      "items": [
        { "kind": "add-node", "say": "加了节点「用户 / 主人」", "place": "o-user", "ids": ["o-user", "…-t"], "quiet": false, "add": [元素…] },
        { "kind": "add-arrows", "say": "连了 nginx 边缘 → webapp、controlplane", "place": "o-nginx", "ids": […], "add": […] },
        { "kind": "expand", "say": "把「webapp」展开成子图", "place": "o-web", "child": "c-web", "change": [元素] },
        { "kind": "rename" | "move" | "restyle" | "delete" | "note" | "link", … }
      ] } ],
  "sources": { "changes": 24, "yourSteps": 2, "unseenEdits": 0, "steps": 26, "dropped": 0 }
}
```

- **元素**是 Excalidraw 元素（`guest_elements`：没有 `customData`，只留指向可达子图的 `childCanvas`），按 `index` 排上下层。一件事的 `add`（新出现）、`change`（换成这一版）、`remove`（消失的 id）就是它落到画布上的改动；`quiet: true` 的（关联代码）不改任何看得见的东西。
- **一次保存 = 一步，一步里有几件事**。一批画出很多东西时，回放把它们一件一件放（节点一个一个、连线按「从哪个节点出去」一组一组），先后由回放定：从小人站的地方起每次取最近的一个（`plan.ts::nearestFirst`），避免来回跑。
- 同一个人相邻不到 10 秒的保存合成一步（`HUMAN_GAP_MS`）：先挪再改名 = 一步里两件事。
- `place` 是小人站着画的那个节点（连线站在起点节点上），`null` 是原地。
- 数量上限：5000 步（超过丢最早的，`dropped` 记下）。

## 5. 分享：开关、网关

- **开关**：分享记录里 `buildReplay: boolean`，创建分享时定，默认 `false`；建好之后主人随时可改：分享窗口「当前分享」每一行有「访客看搭建过程」开关，走 `PATCH /api/share/{id}`（`{buildReplay: bool}`，`ShareManager.set_build_replay`，已结束的分享不能改），访客那边下一次请求 `/api/guest/build` 就按新值放行或 403，已经打开的回放页不被中断。分享窗口里「搭建过程 ☐ 让访客看搭建过程」，下面一行说明：「访客能一步步看到这张图从空白到现在是怎么画出来的，包括画了又删掉、改掉的想法；看不到会话、请求、代码路径或令牌。不勾选，访客只看得到现在的图。」命令行 `agora share create --build-replay`。不替作者定默认，每次分享自己选；列表里每个分享标「访客可看搭建过程」。
- **网关**：`GET /api/guest/build`，和其他访客接口一样要分享令牌 cookie；**分享的 `buildReplay` 不是真就 403**（不是前端把按钮藏起来）；只给分享的那张画布和它下面的（没有 `canvas` 参数，访客没办法要别的画布）；读限流和别的读接口一样。`/api/guest/state` 的 `share.buildReplay` 告诉页面要不要显示按钮。
- **访客页没有访客的小人**：回放的小人只有 agent 和「作者」；访客页不挂任何跟着访客走的东西。

## 6. 评论不绑元素

用户的话：「评论现在不限制必须绑定元素」。主人和访客一样：

- **数据**：线程的 `anchor` 可以是 `null` = 对整张图的评论；可选 `moment: {step}`（写它时在看回放的第几步）。旧线程不变。服务端：访客网关的 `create` 可以不带 `anchor`（带了仍然要指向存在的元素），`moment` 只在分享开了搭建回放时收（必须是 0 到 10 万的整数）；`thread_op` 对 `anchor` 本来就不挑。
- **界面**（`WholeCanvas.tsx`）：画布**右下角**一个「整张图」按钮（挨着帮助按钮，不和缩放、底部工具条挤），带进行中的条数。点开是一个小列表：这张图的整张图评论（谁、多久前、开头两行、几条回复、「回放第 N 步」），底部「写一条」；点一条，右下角出现它的卡片（和钉在元素上的评论卡片是同一个，可回复、编辑、解决、删除）。**不是一个钉子**，画布上没有它的标记。
- **评论列表**（抽屉）里它和别的评论一起（进行中 / 已解决），标签是「整张图」而不是「钉在：某某」，不进「锚点已失效」。
- **钉不钉由评论的人选**：按 C 再点元素 = 钉在元素上；右下角按钮 = 整张图；回放里的输入框 = 整张图 + 那一刻。
- **回放的那一刻**：评论卡片、评论列表里的「回放第 N 步」点一下就打开回放、停在那一步（暂停，可以从那里播）。步的序号是时间线里的 `i`；日志只往后追加，所以序号稳定（压缩过的日志除外：压缩会合并旧记录，老评论的序号可能偏几步，回放里落在最近的一步）。
- **交给 Agent**：作者对整张图评论 @agent 照旧交出去，agent 收到的没有「钉在」这一行。
- **导入的分享包**里的评论保持只读（作者 id 是 `imported:` 前缀）；整张图的评论和它的 `moment` 一起导入。

## 7. 分享包带上日志

`agora share export` 的包里，每块画布多一个 `build`：这块画布的施工日志，**由时间线重造**（`build_log.portable_logs`）：老项目、压缩过的日志都能给出一份完整的；内容只有访客能看到的（元素走 `guest_elements`，没有 `customData`；时间从第一步起算，不带作者的墙上时间）。访客页的「导入到我的 Agora」下载的包，`build` 只在分享开了搭建回放时才有。

`agora import` 校验它和包里其他东西一样不可信：必须是列表、第一条是起始画面且只有一条、每条有整数时间、每个组的 `by` 只能是 `you` 或 `agent`（agent 名字只能是 `[a-z0-9][a-z0-9_-]{0,31}`）、元素走和画布一样的检查（只收基本图形、坐标有限、没有 `customData`、指向包外的子画布链接丢掉）、最多 2 万条；有一处不对就整个包不导入、什么也不写。通过了写成新画布的 `buildlog/<新 id>.jsonl`，导入的人在画布的视图菜单里就能回放。

## 8. 隐私：哪些字段绝不出现在分享里

整个模块的原则是**来源里的私密内容一个字节也不读进输出**：输出从画布元素造，不复制会话里的任何文本字段。逐项（`tests/test_build_log.py`、`tests/test_share_build.py` 扫过输出和日志文件）：

| 绝不出现 | 在哪里 |
|---|---|
| 用户对 agent 说的话（`request`）、agent 的回复文字、每一步的标题和详情（里面有命令行、URL、可能的密钥） | 会话的 turn 记录 |
| 会话 id、turn id、batch id、agent 的原生会话 id、日志路径 | turn / 绑定 |
| 代码路径（`customData.codePaths`）、素材库标记、动画元数据、`customData` 的一切（只留子图链接） | 元素（`guest_elements`；日志写入时就去掉了） |
| 「关联代码」的路径和 glob | 日志里没有；旧项目的派生里只有「把 N 个节点关联到代码」这一句 |
| 会话的名字、模型名、费用、用量 | 绑定 / 会话头 |
| 作者的邮箱、本机路径、机器名 | — |
| 这份分享之外的画布 | 只取 `nested.reachable(root)` |

**和以前不同的一点**：以前的访客版只给「现在这张图按建成先后装起来」，删掉、改写过的东西一概不给。现在按用户的话是**全过程**：作者删掉的想法、改掉的名字访客看得到。这是作者勾选时自己知道的（分享窗口里写明了），不是默认；元素里的文字本来就是画布上的字，若有不想给人看的，删了它也没用——它还在过程里。这一点写在勾选的说明里。

## 9. 和「▶ 回放这一轮」共用什么

「回放这一轮」（`replayMode.ts`、`replayView.ts`）是在**真实画布上**回放一轮会话；施工回放要的是**重建出来的画布**，所以两者只共用下面这些，不共用镜头和切画布的那一套：

| 共用（不改） | 怎么用 |
|---|---|
| `place.ts` `stateAt`、`rig.ts`、`route.ts`、`geometry.ts`、`docks.ts` | 小人的位置、走路、桥、梯子、进出子图的门、气泡；施工回放只造「哪个 agent 在哪个时刻做哪件事」的 `WorkRun`，走路全是现成的 |
| `Overlay.tsx`（`WorkstationOverlay`）、`figureNode.ts`、`bubbles.ts`、`headMark.ts` | 画小人、头、气泡 |

| 新增 | 说明 |

## 10. 子图怎么处理

- 数据里每张画布一份（`canvases`、`start`、每步的 `canvas`），父子关系是「哪张画布、哪个节点」；只包含**可达的**画布（`nested.reachable`）：分享的那张和它下面的。
- 回放的世界给每张画布一个带前缀的 id（`build~c1`），子图链接改写成世界里的 id，所以世界里不会有任何东西和项目真实的画布撞上；每个节点当作一个「文件」，于是**小人去某个节点** = 现有的「小人去某个文件」：文件在父节点的子图里，就是走到父节点、下梯子、切到子图、从入口上方爬下来再走过去（门的时刻、两边同一时刻全是现成的）。
- 排时间（`plan.ts::journeyMs`）：跨画布的一件事 = 在当前画布走到出口 + 一道门 + 在新画布走到位置；每一段走路都按那张画布的真实几何量，所以「画布变了」的那一刻小人确实到了。
- 每张画布各有自己的日志；时间线把它们按时间合并。

## 11. 已知的局限

- 老项目日志开始之前的历史只有 agent 的部分是完整的；人手改的看不到改前（§2）。
- 一批里的东西同一刻画出来，回放里一件一件放是编排，不是它当时的顺序；批与批之间的先后、批内的合并是真的。
- 图片元素（素材库的位图）没有文件内容，回放里不画。
- 走路时间在几何上估，画布中途长出来的桥、梯子路线可能和最终的略有出入，小人到得早晚几百毫秒；落笔按估的到达定，不追赶。
- 手改过的画布如果元素排序键坏了（手写的文件），画出来按文件里的先后叠，不会整张空白。
- 一批画很多东西（一次 19 个节点）时，整张图要几分钟；所以默认倍速按总长选（大约一分半看完），16× 时小人是快跑。
- 日志压缩过之后，更早的过程和老评论的「第 N 步」有偏差（§3、§6）。
- 分享建好后不能改「让访客看搭建过程」，要改就撤销重建。
- 十秒内画了又删的不算一步（§1）。

## 13. 精简 / 逐步（BP1）

用户的话：「展示搭建过程的时候小人走了很多无用的步骤」。`plan.ts` 的 `planBuild(tl, {mode})`：`steps` 是原来的走法，`brief` 是播放器的默认。

**量出来的**（`measure.ts` 的 `walkStats`；三张真实的图，只留几何，文字不进仓库：`fixtures/`）：一个 agent 真实记录的 24 次改图（3 张画布、92 件事）、较小的真实历史、一次画出整张图（用户的真实架构图，没有历史，按「agent 一次画完」算）。逐步的走法里，**无用的走动占走路时间的 65%–100%**：无用 = ① `near`：要去做的那件事离它站的地方不到一臂（`REACH_PX` = 420 世界像素，约两个半节点宽）——站着就能画，却走了过去；② `back`：走过去又走回到两趟之前站的地方附近（A → B → A）。真实历史里 71 趟走动只有 5 趟是必须的，62 趟是 `near`（一趟平均 5 秒：桥、梯子、脚手架都要走）。

**精简怎么做**（都在 `plan.ts`，顺序和因果不动）：
- **够得着就站着画**：这件事（线：起点或终点的节点）离小人站的地方不到 `REACH_PX`，就不走，直接画（这一拍没有 `path`，小人原地）；线从起点节点拉出去，不用走到另一头。
- **走一次，画一片**：确实够不着时，走到「接下来连续几件事」都在一臂之内的那个节点（离它们最近的那个），之后这几件都站着画，不为每个节点各走一次。
- **太远的不走全程**：同一张画布上一趟要走超过 `HOP_MS`（8 秒）的，剪过去：原来的小人不见，新的小人在要画的地方淡入（每次剪切换一个 `WorkRun`，`runsOf`、`figuresAt`；播放器只画每个 agent 当前的那一个）。跨画布（进出子图的梯子和门）不剪，照走。
- **收短**：站着画的一拍时间是原来的 0.6；一步里同类的事仍然按「离得最近的先」排。
- **不变**：步与步的先后不变；一步之内节点在连它的线之前；子图里的事在打开它的节点之后（`brief.test.ts` 对每张图、两种走法都验）。

**结果**（1×；逐步 → 精简；走动距离 = 站的节点之间的距离，走路 = 走路总时长，无用 = 无用走动占走路时间）：

| 图 | 回放总时长 | 走动距离 | 走路 | 走的趟数 | 无用 |
|---|---|---|---|---|---|
| 真实历史（24 次改图） | 451s → 136s（−70%） | 19290 → 4935px（−74%） | 355s → 63s | 71 → 10（剪切 8 次） | 96% → 25% |
| 较小的真实历史 | 108s → 44s（−59%） | 5026 → 2348px（−53%） | 76s → 24s | 17 → 4 | 90% → 80%* |
| 一次画出整张图 | 349s → 125s（−64%） | 16237 → 6913px（−57%） | 279s → 68s | 53 → 12（剪切 4 次） | 69% → 0% |

\* 剩下的是「先去 A 区、再去 B 区、又回 A 区」：步的先后是时间线的因果，不能重排；只有 4 趟。

默认倍速取「总长约 90 秒以内的最慢一档」，精简的真实历史是 2×，约 68 秒。测试（`brief.test.ts`）对三张图断言：精简的走动距离、走路时间、回放总时长都不超过逐步的一半；精简里没有一趟走的是够得着的；同样的事、步的先后不倒退；线不先于它连的节点；子图里的事在展开之后；每个 agent 任何时刻只有一个小人。

## 14. 回放流畅度：复现、测量、根因（BP1，只测不改）

「丝滑」的问题另有导演层去解决（延迟缓冲、小人和镜头共用一份乐谱、速度连续、姿势分层、镜头语言）；这一节是它的输入：在真实页面上（headless Chromium，60fps，我自己的后端，agora-fresh 的拷贝）每一帧采样小人（位置、缩放、透明度、每一根骨头）和镜头（图的变换矩阵），共两段，1× 头 70 秒：逐步、精简。脚本与原始数据在 `round-05/evidence/BP1/`（`bp1-sample.mjs` 采样，`bp1-analyze.py` 统计，`bp1-plot.py` / `bp1-pose*.py` 出图）。

| 量 | 结果 | 根因 |
|---|---|---|
| 帧率 | 60fps，无长帧（p99 16.8ms） | — |
| **小人速度** | 梯形：走 130、爬 220（scene px/s），起步 0→巡航中位 125ms（p90 291ms）、刹车 142ms；**走↔爬无停顿地切换 44 次/70s**，一次 3 帧内 130↔220（加速度 p99 1500、最大 2600 px/s²）；每段之间速度立刻回到 0 再起 | `rig.ts` 的行程按「段」规划：每一段（走/爬/桥）各有恒定的巡航速度，段与段之间不连续（`WALK_SPEED`、`CLIMB_SPEED`），一段内 `prog()` 有缓入缓出，段的交界没有 |
| **镜头（视图）曲线** | 缩放一张画布内恒定（0.654；子图 0.804，换画布时不动画，靠 300ms 交叉淡变盖住）。平移：**逐步里前 25 秒镜头不动**（小人在死区里，离画面中心最远到 523px 才动），之后每次一个脉冲：起步 10–13 帧、持续 1.1–2.5 秒、峰值 17–63px/s。**精简里的每次剪切，镜头在第一帧就达到 141px/s 的峰值**（`toPeakFrames = 0`），再按指数衰减 0.8 秒——速度阶跃 | `BuildStage.tsx` 的镜头：目标点 `fit()` 夹在内容范围里（图放得下时几乎不动 = 死区），再对目标做一阶指数平滑（τ = 0.35s）：目标一跳，速度立刻是 Δ/τ，没有缓入 |
| **不连续的帧** | 逐步 0 处位置跳变。精简：每次剪切一处（9.25s、17.38s…），原小人当帧消失、新小人当帧 0.9 不透明度出现（没有交叉淡变）；换画布 2 处（17.03、54.93s 起 350ms 的两层同时在）：小人在新画布入口出现，镜头缩放 0.654→0.804 | 剪切：`only()` 过滤按布尔值画/不画；淡入是工位视图自带的 320ms，新小人的 `start` 已在过去几毫秒。换画布：每个 `BuildStage` 有自己的镜头，新的一层从自己的初值开始 |
