# 工位视图：agent 在图上干活，时间线能回放

每个 agent（一个会话，以及它派出去的子代理）是图上的一个小人：它读写哪个节点的代码，就走到哪个节点上站着干活。**小人就是指针**——原来的进度指针胶囊、节点紫底都去掉了。下方是工位时间线：每个 agent 一条泳道，拖动就回放；✕ 收成一条 34px 的活动细条。

- 默认打开，⋯ →「工位视图（小人）」可以关（本浏览器 `localStorage` 的 `agora.workstation.v2`）；关掉后每个 agent 在它的节点上是一个紧凑的在场胶囊（头像 · 名字 · 在做什么 · +N）。
- 设计稿：`workbench-focus/index.html` 的状态 a–e（本轮实现）和 f–j（v2，见 §9）；原型：`workstation-proto/`。灵感来自 Loom Studio（loom-studio-sep-2026.moldandyeast.com：程序化小人、按人分泳道、拖动回放）。只参考它公开描述的技术，没有用它的任何代码。

## 1. 数据

- **运行**：顶层是 Agora 会话；子代理是它派出去的（Claude Task / Agent 工具、Codex spawn、经 Seedmux 的 worker），再往下不限层数。服务端 `/api/agent/runs?items=1` 给出每个 run 的条目（前端按和顶层一样的规则切成读、写、执行、思考、等你、派）、`moments`（父泳道上的派发 / 交接时刻）和 `receipts[]`；回执状态沿用服务端的统一状态（dispatched / acked / running / done / idle / session_changed），界面显示时把 `done` 按来源读作「声明完成」（Seedmux）或「已返回结果」（原生），`accepted` 读作「验收通过」，idle / session_changed 读作「状态不明」（`receiptView`）。
- 顶层运行从转录推（确定：同一份日志得到同一条泳道）；`runs/store.ts` 在会话有转录时取运行树，会话在跑时每 3 秒再取一次，把子代理挂到顶层运行下，父运行里派出它的那次工具调用改成「派」片段；服务端没有这个接口（404）时一分钟内不再问。
- **在场**：正在跑，或一分钟内有动静；空闲超过一分钟就淡出、离开画布（`IDLE_LEAVE_MS`），新的工作开始时出现在那段工作第一个节点上，不会从离开前的位置走过来。原来「最后聚焦的会话」永远显示的例外去掉了（它让「Pi App.tsx 10:03」挂了七小时）。

## 2. 小人

- **站在哪**：文件映射到哪个节点（和子图汇总后的有效路径同一套）就站在那个节点的上沿；节点按它看起来的范围算（素材库图标是整组，连同下面的名字）。子图里的文件站在父节点上，气泡里写「↘ 子图 · 订单模块」；映射不到的在图外托盘（放在图里最下面的东西右边，和原型一样，放不下再放左边或图下方；托盘和站在上面的小人都不压东西）。工位按原型的 `dockPoint`：从上沿左端进来 24 px，每人 46 px 起、按小人画出的实际宽度加宽（100% 时小人画成 1.2 倍，间距 54 px），可以沿上沿往右伸出两位；每个工位都要让站着的小人（连头顶的 ! / ?）不压别的文字、图标、箭头标签，节点自己的部分不算；上沿站不下时依次用右侧、左侧（站在节点底线上）、下方（`docks.ts` 的 `dockSpots`）。同一个节点上按树序排（子代理挨着派它的人），位置变化用 Hermite 滑过去。
- **走法（剖面）**：把图当剖面看：节点上沿是台面。换节点时沿两端都绑在节点上的箭头走（最短的一串，按正交长度算）——横着的一段是桥，竖着的一段是梯子（立在箭头竖直那段；没有竖段就在间隙正中；上下叠着的两个节点，梯子在上面那个的侧壁外 10 px）；没有箭头相连、或那条路会穿过节点，就从近处的角搭临时脚手架，越过中间最高的东西 24 px 再下来；去图外托盘总是走脚手架（`route.ts`）。桥和梯子只在走的时候画：桥是腿高度处一条虚线加两端小立柱，梯子是两根竖杆加横档（横档就是手脚踩的地方），脚手架的更淡、虚线，选中的小人的是紫色；行程开始时 200 ms 淡入，到达后 300 ms 淡出。两个台面高差不到 12 px 算「台阶」：不画梯子，脚落到新高度，身体随之上下。走的时候并排的站位偏移滑到 0（小人始终在桥 / 梯子上），到了再滑回自己的工位。
- **短读只看**：读别的节点的文件，连同紧接着在同一节点上的读一共不到 2.5 秒、其中没有写或跑命令，就不走过去——小人留在原地、做「读」的姿态、转向那个节点，从头部到那个节点上沿中点一条紫色虚线，那个节点描 1.2px 紫虚线框（「在读」，看的是图外托盘时托盘也显示出来）。2.5 秒及以上、或接着在那里写 / 跑命令，才在读开始时走过去（`place.ts` 的 `GLANCE_MS`）。
- **子代理**：小一号，头是自己的 agent，头顶角标是派它的人；工作时一根虚线牵回主 agent；派出时出现在主 agent 身边（主 agent 做一个指派的手势），走到自己的文件那里，交回时走回来、转身递过去，然后淡出。只有回执的 worker 原地不动，头顶一个灰色 ?。只画一层子代理，更深的折成父气泡上的 +N（时间线里也不展开）。
- **姿态**：写（紫屏电脑，手在敲）、执行命令（石墨屏终端，按回车）、读（捧着一页纸）、思考、等你（举手 + 提示色问号）、派（指出去）、交接、空闲。头是 agent 的头像。
- **颜色**：紫 = 正在写（节点 1.6px 紫描边、电脑屏、气泡描边），以及每个区域唯一的主按钮；暖色 = 需要你（等你回复、两个 agent 同时写一个文件：节点暖描边、气泡暖底、头顶 !）；其余都是石墨色。
- **气泡**：原型的写法和样式（动词图标、完整路径、「Codex Pi 派的 读 server/users.py 2.4 秒 运行中」「Pi 等你回复 POST /users 要不要登录才能调？〔去回复〕」「Claude Code ✓ 空闲 这一轮做完了」、子代理验收后父气泡上 2.5 秒的「Codex 验收通过」）。主 agent 总有气泡（空闲的也有）；需要你的子代理总有；其余正在干活的子代理（写的优先）补到子代理气泡共 3 个为止。摆放（`bubbles.ts` 的 `placeBubbles`，纯函数，≤4 Hz）按「需要你 → 主 agent → 子代理」：**气泡属于它的小人**——先试原型的位置（`protoSpot`：一个人时在脚左 20 px、头线上 34 px，尾巴指着它，走路时也一样；同一节点几个人时从第一个工位往上每 34 px 叠一个，不带尾巴，靠左边的头像认人）；不行就在头顶左右滑（尾巴始终指着自己的头，两个并排的人各往外伸）、抬一行（细竖线连到头）、或贴在头旁边（侧尾巴）；都放不下时**收成头顶的小签**（动词图标 + 一两个字：读 / 写 / 跑 / 想 / 等你 / 闲 / 走 / 派 / 交 / ?），不会跑到远处。气泡不压节点、文字、图标、箭头标签和站着的别的小人（选中的气泡除外），**两个气泡永远不重叠**；连小签都放不下的子代理才收成上级气泡上的「+N」。气泡锚在小人的脚上（转身、点头不带着它晃），两次摆放之间跟着走路的小人移动或滑向新位置（长距离滑得更久，起停加速度都不超过 2000 px/s²）；逐帧检查：碰到优先级更高的气泡立即隐去、贴近 2 px 内快速淡出，离开后 120 ms 淡回。
- **节点描边**（原型）：有人在写 1.6px 紫，等你 1.6px 暖色，在读 1.2px 紫虚线，其他在干活 1.4px 灰，两人同时写同一文件 2px 暖色宽框；时间线上悬停 / 选中一段时框出它的节点（虚线 / 实线紫）。空闲的小人 62% 不透明。
- 点小人或气泡选中它（出「打开会话」），双击打开会话。

## 3. 时间线

- **细条（默认，34 px）**：左边一句话（「● Pi 写 users.py · API 服务」「● Pi 在等你回复 · POST /users 要不要登录才能调？」「● 2 个会话在干活」「都空闲」，回放时「回放 19:31:45 比实时晚 …」），中间是最多三个主 agent 的活动条（一块 canvas，逐帧画，压缩掉的空闲画成细竖纹），右边是头像和「2 个会话 · 3 个子代理 · ● 1 等你」。拖动活动条就回放；点「工位」或 ⤢ 展开成泳道。工位视图开着时细条一直在：从没有 agent 干过活写「还没有 agent 在干活」，都空闲时写「都空闲」，两种情况后面都有一个小按钮「新建会话」（`ui.newSession()`，`stripRules.ts` 的 `idleStrip` 决定写什么、要不要按钮）。展开成泳道后画布底部让出细条的高度（细条本来就在画布下面，画布随它变矮）；节点若落到缩放条和模式条下面，视图上移或缩小到刚好露出（`stripRules.ts` 的 `yieldView`，只在展开结束时算一次，不放大；镜头取景用的就是变矮后的画布，再扣掉这两个条）。
- **泳道（⤢ 展开，✕ 收回细条）**：头部只有状态胶囊（「● 实时 15:57:50 · 跟随最新动作」/「回放 … · 比实时晚 …」）、播放和 ✕，回放时多出上一步 / 下一步、1× 2× 4× 和「回到实时」——这一条回放条是回放唯一的提示和控制（画布顶部没有另一条）。每个 agent 一行（30 px），子代理在派它的人下面缩进一行（「Codex（Pi 派）」+ 回执胶囊；名字旁的 ▾ 把它们收起），下沿一条无字的回执细线：声明完成不是绿色，验收通过是绿色，状态不明是虚线。片段只写动词 + 文件（读 app.py、写 users.py、跑 pytest、想、派 Codex），等你是暖色；派出 / 交回是竖线；两人同时写同一文件是一条无字的暖色竖带；空闲超过 8 秒压成 88 px 的锯齿段并写明多久；播放头顶端「● 现在」/ 回放时刻，回放时它右边的部分变淡。没有图例和提示文字。
- **悬停一段**出卡片，细节都在这里：谁、做什么（验收的标出来）、文件 / 命令 / 问你的话 / 派给谁做什么、在哪个节点、起止时间和时长、轮次（子代理是它的任务）、验收的是谁、冲突（和谁、什么时候）、派出的回执链，以及「在会话里看」「定位节点」「回放到这里」。鼠标可以移进卡片点按钮；「定位节点」选中这一段并把画布移到小人（不回放）；「回放到这里」跳到这一段的中间进入回放（已经结束的段才有）。悬停时画布虚线框出那一段的节点；点一段只选中它（实线框），卡片留着，不进回放。
- 时间轴按像素自适应刻度，压缩段加起来不超过宽度的 40%；轴比「现在」多留一点（跨度的 2%，0.5–6 秒），走到头才重排，所以两次重排之间已结束的片段不动、不重画。
- **点泳道名**：画布平滑移到那个 agent 的小人上（约 420 ms，缓出），只移这一次，不会一直跟着；你自己一拖一滚就停。悬停出「会话」（打开会话）。
- **回放**：**要明确进入**——只有三种方式：拖动播放头、点细条的 ▶（从头回放）、在一段的详情卡里点「回放到这里」（`clock.ts` 的 `entersReplay`）；单击一段只是选中它（出详情卡，画布圈出节点），单击细条空处只是放开选中，都不进回放，「定位节点」也只选中并平移、不回放。回放中画布一圈淡紫内框，细条变回放条（唯一的提示和控制）；**不动会话面板**（停在你原来的视图上，只有你自己切到轨迹视图时它顶上才有「回放到 …：灰色的是之后发生的」）；**不自动弹跟随标签**（手动点「跟随」照旧，`autoFollowTabAllowed`）；Esc 或拖到最右回到实时，回到实时后镜头继续跟随、没有残留提示；播放跳过压缩掉的空闲，播到现在自动回到实时。

## 4. 性能（P0）

**做法**：结构和动作分开。

- React 只在数据事件和一个 4 Hz 计时器上重建叠层的结构（有哪些小人、气泡、描边）；一个 rAF 循环（`frame.ts`）只改已有节点的属性：小人的每段肢体 `setAttribute`，气泡和胶囊 `transform`，没有 innerHTML，没有每帧的 setState。原来每帧 setState 的 `useNow` 去掉了。
- 整个叠层在一个世界坐标组里，平移缩放只改这一个矩阵；视图从 Excalidraw 的 `onChange` / `onScrollChange` 直接写进 `canvas/viewport.ts`，不经过 React。
- 节点框、落脚点、裁剪区只在场景版本或面板变化时重算；气泡避让 ≤4 Hz。
- 时间线默认只有细条，是一块逐帧画的 canvas；泳道展开时 ≤4 Hz 重建，只渲染可见的泳道；播放头逐帧只改 transform。
- 后台标签页：时间永远从时钟算，不按帧累加；rAF 停了有粗计时器兜底；回到前台第一帧就是对的。被别的 tab 盖住的画布不画。

**预算**：18 个 agent、500 个元素时叠层每帧 ≤ 4 ms。

**测量**：`node web/scripts/bench-overlay.ts <url> <label> --off bare`：Playwright 的 Chromium，1440×900，`?fresh&bench=18x500`（合成的 500 元素图和 18 个一直在读写的会话），CDP `Tracing.start`（`toplevel`、`devtools.timeline`、`blink.user_timing`），每个场景 5 秒：空闲（只有动画）和滚轮平移；统计渲染主线程上顶层 `RunTask` 的时长 ÷ 60 Hz 帧数，叠层的开销 = 开着减去没有叠层（`&bare`）。结果在 `web/evidence/focus/perf/`（保真对照那次在 `web/evidence/fidelity/perf/`）。

| | fps | 主线程 / 帧（空闲） | 主线程 / 帧（平移） | 叠层开销 |
|---|---|---|---|---|
| 改之前（12f78eb，工位视图开） | 4.6 | 238 ms（每实际帧） | 168 ms | 渲染进程跑十几秒会崩 |
| P0 之后 | 60 | 2.31 ms | 3.47 ms | 1.8 / 2.5 ms |
| P2 之后（含动效） | 60 | 3.25 ms | 3.75 ms | **3.0 / 2.7 ms**（帧任务本身 0.43 ms） |
| 保真对照之后（泳道展开） | 60 | 3.95 ms | 4.56 ms | **3.7 / 3.3 ms**（帧任务本身 1.29 / 0.55 ms） |

泳道展开时靠这三条守住预算（`web/evidence/fidelity/perf/bench-fidelity.json`）：片段用 `left` 定位而不是 transform（每段一个 transform 会各成一个绘制块，3D 的还各成一个合成层，每帧的 layerize 都要付钱）；泳道区自成一个合成层（`contain: layout paint` 加 `will-change: transform`），画布上的动画不会让它重画；已结束的片段、泳道名按内容记忆，4 Hz 重建只动正在跑的那一段。

## 5. 动效（P2）

一条原则：**什么都不跳**。

- 走路（台面、桥、台阶）：起步前转身；远侧脚先迈，等长的步子，每步落在身体前半步、抬起时在身体后半步，最后一步落到工位、另一只脚跟上；身体沿路线连续滑行——加速、匀速、减速三段，速度连续；摆臂跟对侧脚、上下起伏跟步子、微微前倾；过台阶时身体在台阶前后一段里平滑升降；到了带一点阻尼回弹。
- 爬梯：走到梯子跟前停下，离梯子 4 个小人单位、面向梯子（从哪边来就站在哪边）；手脚在走路减速的最后一段和爬梯起步的第一段里（各不超过 150 ms）上梯，身体不停顿、速度连续。梯子上躯干直立略朝梯子、膝盖弯，手脚都踩在横档上：对角成对（近侧手 + 远侧脚、远侧手 + 近侧脚）轮流移动，一对移动时另一对抓牢，身体连续上下；到顶跨上台面、到底踩到台面，手离开梯子后再转身往前走。横档约 5.5 个小人单位（× 小人比例，按梯子高度均分），竖杆高出上层台面约 22 单位当扶手。
- 时长与步速（2026-09-29 用户决定调慢走路，原先整趟夹在 0.7–2.4 秒、远路被压到约 600 px/s，看起来像在跑）：走路步速顶到 0.22 px/ms（每秒 220 px，一步约 5 帧）、爬梯 0.13 px/ms（这是主 agent 的；子代理按比例小 0.8 倍，步子的节拍不变）。一段路的时间 = 长度 ÷ 步速 + 起步和收步各 0.3 秒的加减速（路短时加减速各占这段时间的 30%），所以远路和近路迈的是同样的步子，不再越远越快；整趟（含起步转身 0.24 秒）**没有上限**，下限 0.7 秒（更短的整体放慢，步子变小）。每段都从静止到静止，加速度不超过 0.005 px/ms²（60 fps 时一帧的速度变化不到 1.4 px），太短的一段因此保底时长。摆动脚每帧最多移动 12 px，一次迈步不少于 4 帧（`trip.test.ts` 锁定）。回放里行程跟着时间线走：慢放（`clock.motionScale`）照旧生效。
- 下一段工作在小人还没走到时就开始：**走到再出发**（`place.ts` 的 `step`）。新的一趟从上一趟的终点、上一趟到达的那一刻起，接着走，位置始终连续，不会瞬移，也不会半路折回；等的这段时间里它继续走完上一趟，新工作的姿势（写、读…）在它出发走到新节点之后才开始。这条规则对回放和实时一样（纯函数：新一趟的开始时刻 = max(那段工作的开始时刻, 上一趟的到达时刻)）。
- **门的两边同一时刻**（`place.ts` 的 `door.enter` / `door.leave`、`doorTiming`；`subview.ts` 的 `outer`）：走路调慢后走到门口要几秒，所以子图那张画布上的小人不再按工作段开始时刻出现，而是主画布上它**走完进门动画（`doorsIn` + DOOR_MS，`portalPhase` 变成 `behind`）的那一刻**才在入口淡入放大、再走到目标节点；出门反过来：子图里走到入口、进门淡出之后，主画布上才出来。两边各自向对方要门的时刻（子图向外层要 `enter`，外层向子图要 `leave`，且向子图要的是不带这两个函数的版本，不会互相追问）。跟随窗口（`presenceAt`，FollowPane 传入主画布的上下文）也用这一刻：在门外走的时候不算"进了子图"，窗口不弹；进了才弹，出门走完才回到主画布。只用 ≤t 的数据，回放与实时一致。已知：子图深过两层时只按最近一层已发布的画布对时；跟随窗口的自动弹出每 250 ms 查一次，比主画布进门晚 ≤ 0.25 s。
- **追赶（不无限累积滞后）**：新工作段开始时，如果小人还在路上、按计划到达的时刻比这一刻晚 1.5 秒以上（`CATCH_UP_MS`），就放弃中间站，从它此刻的位置和脚的位置（不停步、不再转身停顿）直接规划去最新工作段的地点，位置连续、不瞬移；这一趟步速 1.5 倍（`BOOST`）。晚不到 1.5 秒的照旧「走到再出发」，但等了超过 1 秒才出发的那一趟同样 1.5 倍（`BOOST_AFTER_MS`）。另外，一个等着出发的中间站，如果在它出发之前又有更新的工作开始了，就直接作废（从没出发过）。同样是纯函数，回放和实时结果一致。测试：`chain.test.ts`（10 段、0.5 秒一段来回跳，任何时刻落后 ≤ 3 秒，实测最大 1.6 秒；位置每帧 < 6 px，实测 5.5 px）。已知：追赶时从路上直接转向，速度会有一次折返（位置连续、脚不跳），被放弃的中间站在「追踪」里仍会列成一站。
- 转身（起步、到了、交回时转过去递东西）：整个身体水平翻过去，经侧身，200 ms（墙上时钟，缓入缓出），实时下起步时转完才迈第一步；半路再反向就从当前的角度转回去；头像、派它的人的角标和 ! / ? 不跟着镜像；跳时间时直接朝向新方向。
- 姿态切换经弹簧 250–400 ms 过渡；道具淡入缩放；弹簧按墙上时钟积分（16× 回放也按人的速度过渡），只在真正跳时间（拖动、跳到某刻、回到实时、后台回来）时复位。帧循环给的时间只进不退：每帧用该帧自己的时间戳，数据更新后补画的那一次沿用上一帧的时间，所以不会被误当成跳时间（弹簧复位、转身被截断）。
- 小人出现淡入、离开淡出；并排的位置和气泡的位置都用 Hermite 滑动（从静止起步、中途改目标速度也连续）；气泡 180 ms 淡入上浮、120 ms 淡出、换字交叉淡入、耗时数字等宽定宽；节点描边 300 ms 淡入淡出换色。
- 时间线：泳道和原型一样每 250 ms 重建，片段不做过渡（18 个 agent 时每段一个过渡会让样式重算每帧都跑），正在跑的那段每 250 ms 长一截；细条逐帧画，播放头逐帧外推，轴重排时从当前位置 300 ms 缓动到新位置；展开收起动画高度（340 ms），这时画布保持上沿不动，图和小人不跟着滑。
- 亚像素位置（`translate3d`、SVG 小数），先读尺寸再写；回放状态给 React 的更新限到 ≤4 Hz。
- 减少动效：不走路（没有行程、不画桥梯）、四肢不动，但位置变化是淡出—淡入的交叉，不硬切；短读只看照样（原地转向、虚线）。

**证据**：`node web/scripts/motion-capture.ts <url> web/evidence/focus/motion [--dark] [--reduced]`：`?mock=runs` 的脚本，逐帧记录 rAF 时间戳和每个小人（整体位置，取点击框；转身和四肢不在这项统计里）、气泡、播放头的屏幕位置，统计掉帧、最大帧间隔、>25 ms 的卡顿、以及「这一帧的位移和上一帧相差 >2 px」的不连续（透明度低于 25% 时的交叉淡变不算）。窗口：bridge（Claude Code 过 HTTP 桥）、ladder（Claude Code 在 API 服务旁下梯、Pi 在 SQL 竖段 x = 610 上梯）、pose、bubbles-enter、scaffold（Codex 走脚手架去图外托盘）、glance（Claude 子代理在支付服务原地看图外的 docs/payments.md）、handoff-exit、replay-scrub；窗口按时间先后录，不重叠。每个场景有 MP4 和 GIF（剖面的几个窗口裁画布区）。

## 6. 取舍

- **剖面而不是轴测**：画布是用户自己画的平面架构图，斜过来会破坏图本身。把它当剖面看（节点上沿是台面、箭头是路），小人沿用户画的连线走，图不变，桥梯只在走的时候出现；斜的箭头按正交长度算，梯子可能压住竖段上的箭头标签。原先「从空中越过方框」的走法看着像飘，删掉了。
- **读也移动小人，短读除外**：只看写的话小人大部分时间站着不动；「在看哪」本身有用。一眼就看完的读（不到 2.5 秒）走过去又走回来太闹，改成原地转向、虚线指过去。
- **一个主 agent 带子代理是常态**：两个顶层 agent 同时干活很少见（之后宿主会加运行锁），所以不做多顶层的拥挤规则，只保留一个兜底：同一节点并排站。
- **图外托盘贴着图**：不是屏幕角落，拖动画布时跟着图走。

## 10. 子视图跟随

子图（[nested-canvas.md](nested-canvas.md)）里有 agent 在干活时，窗口管理器里出现一个「跟随」标签页（只读），跟着它进出子图；标签页不动你的画布（只有里面的「在主画布打开」会换层）。主 agent 例外：镜头默认会带着主画布跟它走（见下面「默认跟随」），那时不弹标签；关掉镜头跟随后，你自己的画布不动、不换层。这是 §9「子图」「跟随窗格」两条里「在窗口管理器里加跟随组类型」的那一部分。

| 文件 | 做什么 |
|---|---|
| `subview.ts` | 纯函数：`levelsOf` 一个文件在主画布之下的层级；`presenceAt` 一个 agent 在 t 时刻站在哪一层、从什么时候起在子视图里干活；`arrivals` 窗格该对谁作出反应（`subview.test.ts`） |
| `follow.ts` | 共享状态 `{ run, ended, auto, pinned }`：`start(run, { auto })` / `end()` / `stop()` / `pin()`；`paneView` 是窗格里一张画布的叠层 id（`follow:<画布>`） |
| `FollowPane.tsx` `follow.css` | `FollowPane`：App 层挂一个，不画东西，管自动打开、收起和让标签在布局里进出；`FollowView`：标签页的内容；`FollowMark` `useFollowTitle`：标签的头像和「跟随 · <agent>」 |
| `../workspace/followTab.ts` | 纯函数：`FOLLOW_TAB`（虚拟标签，不是文档）、`followHome`（放进哪个组：会话组上方 / 画布右边一栏）、`insertFollow` / `withoutFollow`、`spotOf`（你拖到哪了，这一次页面里记住）；`splitOff`（`layout.ts`）在目标组旁切出新组（`followTab.test.ts`） |
| `EntryMarks.tsx` | 父图入口提示，挂在叠层 `.ws-layer` 里 |

- **在哪一层**：从主画布往下，节点「只经它的子图」认领一个文件（不是节点自己的路径）就下一层，到那张子图里找认领它的节点，一直到底：总架构 › API 服务 › 用户模块。子图链成环时在重复的画布处截断；子图不在了就停在指向它的节点。和 `geometry.ts` 的 `locate` 同一套判断，只是 `locate` 只下一层（小人站在父节点上，气泡写「↘ 子图 · X」）。
- **谁在子视图里**：`stateAt` 的规则不变，只把地点换成最深那层的节点，所以短读只看、子代理从派它的人身边出发和交回、空闲离场都和画布上一致。「进入」的时刻 = 它上一次去主画布上（或图外）的文件之后，第一个子视图里的文件开始的时刻；在子视图之间走、往更深走不算新的进入；只是站在那里（第一份文件之前、刚被派过去、交回中、空闲）不算在干活。
- **自动弹出（默认关）**：页面默认不自己弹窗口，跟随标签只在你点「跟随」时打开（小人头顶的按钮、泳道名、子图入口上的头像都算）。「⋯」里的开关「有 agent 进子图时自动打开跟随窗口」（`app/prefs.ts` 的 `autoFollowTab`，默认关，每个浏览者自己的）打开后，才是下面这条：任何 agent（主或子代理）开始处理子视图里的文件，窗格弹出并跟随它；回放时也不自动弹；同时有几个在子视图里时，顶部一排头像（按树序，不跳位）可切换，默认跟最近进入的那个，后来进入的会接过去。它离开所有子视图，窗格停在原处写「回到 总架构」；它结束（空闲、子代理交回）写「已结束」；约 3 秒后收起——钉住或鼠标停在窗格上时不收；那时还有别人在子视图里干活，就直接换成其中最近进入的那个。同一次进入只弹一次：你关掉后，它要离开再回来才会再弹。工位视图关着时不自动弹。
- **手动**：选中小人按 F，或点它的「跟随」（`follow.start`），它在主画布上也打开，显示它当前所在的画布（图外时就是主画布）。手动跟随不会被新来的 agent 抢走（它们只加入头像行），它离开子视图也继续跟，结束时同样写「已结束」、3 秒后收起。标签里的按钮：钉住 / 在主画布打开（`nav.go` 把主视图换成这张子图，标签随即关上）；停止跟随是标签上的 ✕。全局键在 App 层一处：Esc = `focus.escape()`（先退追踪 → 再停跟随 → 再清选中），F = 跟随选中的小人；焦点在输入框或时间线里时不接。
- **窗格里画什么**：那张画布的只读画面（Excalidraw `exportToSvg`，按画布、场景版本和主题缓存，不导出背景和框名，字体用页面已加载的）加上同一个 `WorkstationOverlay`——给它一个合成的视图，id 是 `follow:<画布>`，有自己的视口和小人位置——所以小人在里面照样走桥、爬梯、站在子图节点上。镜头：整张图放得下就整张（缩放 55%–100%），放不下就平滑跟着被跟随的小人（指数平滑，时间常数 0.35 s），不跑出图（小人在图外托盘时把它也框进来）；镜头的帧任务注册在叠层的帧任务之前，画面和小人同一帧移动。往更深或回上一层时两张画布交叉淡变 300 ms。
- **父图入口**：有人在某个节点的子视图里时，这个节点左下角一个小胶囊放里面 agent 的头像（三个，再多 +N；点头像跟随它），有人在里面写时节点外一圈淡紫（`--accent-soft`）；里面有人在等你时，入口用和别处「等你」一样的暖色（外圈换暖色、胶囊里多一个暖色圆点，悬停写「等你回复 · 名字」），你不进子图也看得到；减少动效时只保留颜色。它按叠层的视图算，所以窗格里的子画布上也有（`follow:` 前缀认回画布）。
- **默认跟随**（`liveCamera.ts` `replayLive.ts`，镜头本身是 §11「放这一轮」的那一套 `replayView.ts` 推广到实时；`liveCamera.test.ts`）：页面打开后，主画布的镜头默认跟着**主 agent**——你正在对话的那个会话（`pointerFollow` 且它的标签开着）的顶层运行；没有焦点会话时，跟最近在干活的顶层运行（正在干活的优先，再看最近一次干活的时间）。跟法和放一轮一样：约 100% 缩放、死区、平滑（约 0.3 s），扣掉顶部被占的区域，小人、目标节点和气泡装不下就缩小（下限 70%）；小人进子图入口、进了门的那一刻，主画布切进那张子图（`nav.go`，面包屑和「返回」都在），出门切回来，两张画面交叉淡变；减少动效时直接切、直接到位。它空闲（运行不在干活）时镜头不动，也不切画布，有新工作再推近。
  - **暂停和恢复**：你手动拖动或缩放画布、在画布上选中或编辑元素（点画布、在文字编辑框里打字）、打开评论（点评论工具条）、按 Esc、自己换到另一张画布，镜头就暂停；画布顶部中间出现「跟随 <agent>」（`ws-live-bar`，只写 agent 名如「跟随 Claude Code」，完整名字在悬停提示里），点一下恢复。暂停不是关掉：不存，刷新页面又是默认开。暂停时你在哪张画布就停在哪张。
  - **空的会话面板**：还没有消息时不弹窗，只写三行怎么用（在这里告诉 agent 做什么；干活时图上的小人带你看它在改哪；在图上留评论、点「交给 …」）。
  - **总开关**：「⋯」菜单里「镜头跟随主 agent」，默认开，每个浏览者自己的偏好（`app/prefs.ts` 的 `followCamera`，存在浏览器里，不写进项目）。关掉后画布完全不动，回到原来的行为；镜头正带着你在子图里时关掉，画布回到你原来的那张、原来的视图（不留下镜头带你去的痕迹）。
  - **优先级**：放一轮 > 追踪 > 默认跟主 agent（`liveCamera.ts` 的 `pickFollow`）：放一轮时由放一轮的镜头接管（实时镜头先回到你的画布再让位），放完回到实时跟拍；追踪某个 agent（包括子代理）时镜头跟被追踪的那个；时间线在回放（不是实时）时镜头不跟。放一轮是你主动要的，所以总开关关着它也照样动。
  - **只跟图上的工作，做完回去**：镜头只在被跟的主 agent 在节点上手里有文件（读、写）、在路线上走、在子图入口进出时推近（`liveCamera.ts` 的 `whereOf` / `followsWhere`）；它站到「图外」托盘（没落到任何节点）、只在想（没有文件在手，比如只回复一个字）或空闲时，镜头保持原样。没有图上的工作约 3 秒后（`HOME_AFTER_MS`，「✓ 这一轮做完了」出来之后），镜头平滑回到开始跟拍前你的画布和视图（和放一轮放完回去是同一套：在子图里就切回来并放回原视图，在原画布上就缓动回原视图）；你暂停或接管过的不动（`goHomeDue`）；有新工作上图再推近；减少动效时直接回去。
  - **不留痕**：镜头自己带着切画布时，不保存项目布局（`replayQuiet.ts` 让 `persist.ts` 暂停 workspace 那一项的保存，切走的第一刻到回来之后才恢复）、不往浏览器历史里推记录（`replacingPush`，切画布的 push 换成 replace）、不弹「在子图里」的一次性提示、不弹「可能过时」（`NestedLayer` 用同一套静默，`replayQuiet.ts` 的 `staleVisible`）。你自己点进子图、换画布，照常保存、照常推历史。
  - **和跟随标签**：镜头正跟着主 agent 时，主 agent 进子图不再弹标签（镜头已经带你进去了）；子代理和别的顶层 agent 进子图照旧弹；关掉镜头跟随、或暂停时，主 agent 也照旧规则弹（`liveCamera.ts` 的 `mayOpenFollowTab`，`FollowPane` 用）。
- **位置**：第一次打开时，画布右边已经有会话组的话，在那一栏的上方竖着切出来（跟随在上约 50%、会话在下），画布宽度一点不变——三栏并排会把画布挤得太窄；右边没有会话组时，才在画布右边切一栏（跟随约 40%）。之后你把标签拖到哪个组、哪条边，就在哪（拖到别的组里就并成那个组的一个标签，拖到边上就是自己一个组）；它自动收起再打开时回到你上次放的地方，只记在这一次页面里。标签上的 ✕（或右键「停止跟随」）等于停止跟随；不能重命名、不能删除。它是临时的：**不写进项目的 `workspace.json`**（`model.ts` 的 `savedWorkspace` 把它和只放它的组去掉）。
- **动效**：换画布时两张画面交叉淡变 300 ms；标签进出用窗口管理器自己的滑动。减少动效：直接出现、直接消失，换画布不交叉淡变，镜头直接到位，小人按 §5 的规则。
- **局限**：窗格里的叠层只画在这张子图里的人和被跟随的那一个，别人不画（不会站到它的图外托盘上）；小人从入口进门、出门的动画见 §12。

## 11. 追踪

点一个小人（或它的气泡），或点时间线上它的泳道名，就只看这一个 agent 走过的路：其余变淡，它去过的节点按顺序编号，路线沿它走过的桥和梯子画出来，子图入口标成传送点，子代理从派出到交回一条细虚线，时间线只剩它和它的子代理。这是 §9「Agent 树与追踪」里追踪的部分（状态 j），不做树面板。

| 文件 | 做什么 |
|---|---|
| `trace.ts` | 纯函数 `traceAt(run, t, ctx)`：它依次去过的地方（`stops`：节点或图外托盘，出发和到达的时刻，t 时到没到，在那里经子图入口进过哪张子图、去了里面哪些节点）；每两站之间那一趟的腿（`ways`：和行程同一条路线——同一对落脚点、同一张走图，桥和梯子就是从这些腿画出来的）；它的每个子代理从哪派出、去过哪、在哪交回（`subs`）。`walkedAt(way, t)`：这一趟到 t 走了多长（`trace.test.ts`） |
| `focus.ts` | `traced` 与 `focus.trace(id, turn?)`；`turn`（`TurnWindow`：轮号、起止，`end` 为 null = 还在跑）与 `traced` 同在这一个 store，`focus.escape()` 先退追踪（也就放掉轮）；`traceTurn`、`hoverItem`、`panToItem` 见「按轮追踪」 |
| `Overlay.tsx` `workstation.css` | 追踪层（变淡、编号、路线、传送点、子代理虚线）和小人的动作行 |
| `Timeline.tsx` | 只剩它的泳道、泳道名的点击与悬停菜单、「追踪中」、细条那句话 |

- **进入与退出**：点小人或它的气泡 = 选中并追踪它，再点一次两样都放开；点泳道名 = 追踪它，并把画布平滑移到它（原来的「定位」，只移一次）。选中的小人动作行是「打开会话 · 跟随 · 退出追踪」（没在追踪它时是「追踪」）；泳道名平时只有名字和一个状态标记（「追踪中」，名字太长以「…」结尾，不被标记挤掉），悬停或聚焦时第二行出现短按钮「会话 · 追踪 / 退出 · 跟随」（完整的字在提示里，`stripRules.ts` 的 `laneLabel`），泳道名可以用 Tab 聚焦、回车。Esc 先退追踪：画布上由 App 层的全局键，时间线里（泳道名、按钮、播放头上）由时间线自己；再按一次才停跟随、清选中或回到实时。追踪和跟随可以同时开。
- **变淡**：其余小人和它们的气泡、描边、牵绳、桥梯、「在读」虚线都降到 30% 不透明，点不到；追踪的 agent 和它各层的子代理不变，它的气泡总在。变淡立即生效，不等重建。
- **编号**：到访的节点左上角按顺序一个编号小圆（①②③…，再到同一个节点就接在上一个下面），走到那里（行程结束时；减少动效时是出发时）才实心，没到的空心淡色——回放时之后才到的那些就是这样。列的是 t 所在的这一段工作（空闲一分钟离场，下一段重新从 ① 算；子代理是它从派出到交回的这一趟），只列已经发生过的：实时时没有未来的站。
- **路线**：走过的路沿它走的桥和梯子画成一条细的主题紫线（就是行程的腿：台面上贴着节点上沿，过桥、上下梯子都在桥和梯子的位置，没另算一套）。正在走的那一趟跟着小人往前长，线头在它脚下（爬梯时它离梯子 4 个小人单位）；进入追踪时整条路线从 ① 起 650 ms 描出来。
- **传送点**：在某个节点经子图入口进过它的子图，第一个编号旁、节点上沿里面一个「↘ 子图 · 应用入口、用户模块」小胶囊（到 t 为止在那张子图里去过的节点，按顺序）。
- **子代理**：每个子代理从派出点经它去过的地方到交回点一条灰色细虚线（去和回各向一边弯，成梭形），出去那一段的正中放它的头像；交回之前线不回来。只有回执的 worker 不走，没有线。图外托盘上有站或经过时托盘显示出来。
- **拖动回放**：编号和路线跟着播放头变——到访顺序只算到 t，路线长到 t 时小人所在的地方。
- **时间线**：只剩它和它的子代理的泳道（收起的子代理照样收起），它的名字旁一个「追踪中」；细条那句话说它（「追踪 · ● Pi 写 users.py · API 服务」；回放时说它在播放头那一刻做什么），活动条只画它和它的子代理；右边的会话计数不变。退出后恢复。
- **结构与每帧**：编号、路线、虚线都随叠层 ≤ 4 Hz 的重建算；帧循环只让正在走的那一趟的线往前长（改一条 path）、切编号的实心、视图移动时挪标记。退出时整层 200 ms 淡出。
- **减少动效**：不描线，路线在出发时直接出现；标记和变淡照样是淡变。
- **跟随标签里**：画面同样变淡，编号和路线只画在你自己的画布上。

### 按轮追踪：把一轮会话的工具调用画在图上

追踪的范围是**会话的某一轮**，不再是「t 所在的那一段工作」：站点、路线、子代理都只算这一轮里的。点小人或泳道名进入时默认就是它当前（或最近）的一轮（`latestTurnWindow`：从片段的轮号 `RunSeg.turn` 推）；从会话进入则是那一轮的 `[startedAt, endedAt]`，正在跑的一轮 `endedAt` 取「现在」，所以站点随新的工具调用增加（实时和回放都行；回放里 t 之后的站是空心的）。

- **入口（会话里）**：每一轮的头部——对话视图的 `第 N 轮` 行、轨迹视图的轮头——有「在图上看这一轮」和「▶」（`session/TraceTurn.tsx`；这个会话还没出现在工位视图里时两个都灰）。前者 `focus.traceTurn`：追踪这一轮、选中它，画布**平滑移到第一个站点**（`canvas/glide.ts` 的 `glideTo`，和泳道名找 agent 是同一个平滑平移，只在点的时候动，之后不跟着）。「▶」追踪这一轮并用时间线自己的回放（`clock.play`，展开泳道后有 .25×–4× 的速度键，可以慢放）从这一轮开头放到结尾，追踪在回放期间保持；这是你主动要求「放一遍」，所以这时镜头会动（见下面「放这一轮」），平时的实时画布照旧不动。
- **放这一轮**（`replayMode.ts` `replayView.ts` `replayFollow.ts` `replayFit.ts` `replayCamera.ts` `replayDom.ts` `replayHistory.ts` `playCounts.ts` `ReplayBar.tsx` `ReplayMarks.tsx` `replay.css`）：
  - **镜头**：以被追踪的 agent 为中心跟拍，约 100%（最大 125%）让节点文字清楚，小人、它正去的节点和气泡装不下就缩小，最小 70%；`replayFollow.ts` 的纯函数 `followView` 算目标视图和要不要动（死区：小人离画面中心不远时镜头不动），每个动画帧以约 0.3 秒的时间常数追过去；扣掉顶部工具栏和横条占的高度（`replayDom.ts` 从 DOM 量）。开始先看一眼总图（约 1 秒）再推近；放到这一轮结束后拉远回总图，说汇总。
  - **进出子图**：小人在总图上走进子图入口、进了门（`portalPhase` 是 `behind`）的那一刻，主画布切进这张子图，和你点进子图一样（`nav.go`，面包屑和「返回」都在），切换是两张画面的交叉淡变（View Transition，约 320 ms；减少动效时直接切），落在小人附近的放大视角（`canvas/viewport.ts` 的 `firstView` 把视图交给新挂载的画布）；它出门就切回。`replayCamera.ts` 的 `cameraCanvas` 是纯函数。这时不弹跟随标签（`FollowPane`）。
  - **节点亮起**：这一轮改到的节点描紫框，右上角「+N」是到这一刻这一轮（含它派的子代理）在该节点写了几个文件（同一文件只算一次，`playCounts.ts`）；父节点在总图上显示子图里的合计；放完汇总浮标「这一轮改了 X 个节点、Y 个文件」放在最后写的节点上方的空处，避开连线标签，放不下就写在横条里（`replayFit.ts` 的 `placeBadge`）。
  - **横条**（`ReplayBar`）：「第 N 轮 · <会话名>」、退出（Esc）；你手动拖动或缩放画布，镜头就停止跟拍，横条出现「跟随小人」，点一下恢复（只在这一次放的过程里，不存）。
  - **放完**：汇总停几秒后自己结束，回到开始前的那张画布和视图，时间线回到实时，镜头回到 §10「默认跟随」。放的过程中：不保存项目布局（`persist.ts` 暂停 workspace 那一项的保存）、不往浏览器历史里推记录（切画布的 push 换成 replace）、不弹「在子图里」的一次性提示。
- **站点就是工具调用**（`Stop.calls`，`trace.ts` 的 `attachCalls`）：悬停编号，列出这一轮在这个节点上的调用，按时间：`Read server/app.py`、`Edit users.py`、`Bash pytest …`、`问你：…`；子代理写「派出 Codex：<任务>」和「Codex 交回」（派出那一行读不出是哪个子代理时，认领紧接着它派出的那个，不重复列）。一个文件的调用算在它那个节点最近的一站（走过去的那一步比调用晚一点开始也算），没有节点认领的文件算图外托盘那一站，项目外的路径（scratchpad、/tmp）和没有文件的调用（想、跑命令）算在小人当时站的那一站；思考不算调用。图外托盘也是一站。
- **点站点**：会话面板切到轨迹视图，展开这一轮，并**滚到这一站的第一步**，这一站**所有**有转录条目的调用行一起亮约 1.5 秒（`agora:step` 事件带 `itemId`（第一步）和 `itemIds`（`trace.ts` 的 `itemsOfStop`）；`SessionPane` 收 `itemId` 滚动，`TrajectoryView` 自己也收 `itemIds` 决定亮哪几行）；多轮时站点属于它那一轮（事件里带 `turn`），第 2 轮的站点跳到第 2 轮；这一站没有条目就滚到那一轮的头。
- **反过来**：轨迹视图里悬停一次工具调用（`RecordRow`），画布上它的节点亮一圈（和悬停站点是同一种虚线圈）、它所在那一站的编号高亮，移开恢复（`focus.hoverItem`）；**随时生效，不用先进入追踪**，站点和编号只在追踪中或「在图上看这一轮」时才有。那一步在子图里时亮的是主图上的子图入口节点（`geometry.locate` 把子图里的文件算在入口节点上）；没有落到任何节点的调用（`cd`、纯命令、项目外文件）不亮，也不报错。点它，画布平滑移到那个节点（`focus.panToItem`，一次）。行和站点靠同一个条目 id 对上：轨迹行的 id 就是工具调用的 `toolu_…`，站点里的调用带的 `itemId` 是同一串（真实会话 `s-7xzd5n5` 的 12 个调用逐个对过，`trace.test.ts`「a real session」）。
- **纯函数**（`trace.ts`）：`traceAt(run, t, ctx, known, win?)` 的 `win` 给出这一轮；`turnWindowOf`、`latestTurnWindow`、`spanOf`；「轨迹步骤 ↔ 站点」是 `stopForItem`（条目 → 哪一站，含子代理的）、`itemOfStop`（站 → 它的第一个有条目的调用）和 `itemsOfStop`（站 → 它所有有条目的调用，按时间）。测试在 `turnTrace.test.ts`。一轮落在更长的一段连续工作里时，这一轮的第一站是它开始时小人站的地方，不带前几轮的路。

## 12. 评论联动与进出子图

- **认出评论轮**：「交给 Agent」发出的消息第一行是「画布评论 #n（锚点：名字（id）、…）：」（`comments/handoff.ts`）。`lanes.ts` 的 `commentOf` 从这一轮的用户消息读出编号和锚点元素 id，这一轮的每个片段带上 `comment: { n, anchor }`（还在进行的轮次加 `open`）；只从转录推出，不另存状态，回放照样。`place.ts` 的 `commentSpans` 把它们连成一段（首个片段开始到最后一个结束）。
- **位置**：评论轮里没有文件的片段（想、跑命令、问你）在锚点所在的节点做；读写文件照常去文件的节点，短读只看、桥 / 梯子 / 脚手架都照旧。锚点 → 节点（`scenePlaces.ts` 的 `anchorPlace`）：元素本身是被链接的节点就是它，否则取中心落在其中的最小节点框（文字、贴在上面的便签、图标的笔画），都不在就取最近的节点，图上一个节点也没有才去图外托盘；锚点不在这块画布上时这一轮没有自己的位置（子画布上则从入口出去）。
- **效果**（`CommentWork.tsx`，挂在评论层里）：评论轮进行中，钉和小人头部之间一条 1.2 px 的紫色虚线（向上微弯，越过中间别人的头），随小人淡入淡出；这一轮结束、答复贴回线程时，钉上弹出一个紫底对勾（约 600 ms：弹出、停留、淡出，外圈一道扩散的细环）。回放按转录里的结束时刻；实时下数据晚到几秒也补放一次。减少动效：线和对勾只出现、消失，不做动画。`RunState.answered` 在答复后 1 秒内给出，小人在答复那一刻（`answeredAt`，时间线时间）点一次头（`gestures.ts`，约 0.7 秒；减少动效时不点）。`?mock=runs` 在 58–66 秒有一段：Pi 处理 Redis 上的评论 #3「缓存过期时间是不是太短？」（钉只在 mock 里显示，不保存、不可点开）。
- **进出子图**（`Ctx.door`）：文件在某节点的子图里时，小人走到这个节点，在节点上沿缩小到一半并淡出（400 ms，`portalPhase: "in"`、`portalScale`、`fade`），之后不在这块画布上（`present: false`，入口处由子视图的头像表示）；做完出来时反过来，先在原处淡入放大，再走向下一个节点。子画布上入口是离左上最近的节点：不在这块画布上的文件都在入口后面，小人从入口淡入放大出现再走过去，离开时走回入口进门。一段工作从子图里开始时，一开始就在里面。派出的子代理跟着派它的人在门里门外；交回给在门里的人时走到门口进去，不在外面交接。减少动效时只淡入淡出，不缩放。没有 `door` 的上下文（子视图、追踪的计算）照旧站在节点上、气泡写「↘ 子图」。

- **「交给 Agent」发给谁**（`session/pickSession.ts`、`ops/agent.ts` 的 `handTarget` / `handToSession`）：按顺序取——① 窗口管理器里此刻开着（`SessionPane` 挂载即登记进 `ui.ts` 的 `openSessions`）、关联这块画布、且是最后聚焦的会话（`pointerFollow`，人正看着的那个）；② 其他开着的关联会话，最近活动的在前；③ 这块画布上最近活动的关联会话；都没有就打开选择器（`ui.chooseAgent`）让人选。**「还能收消息」不猜**，直接读服务端推来的状态（`sendable`，与 `sessions.send` 的判断一致）：没绑定、是 `cp -r` 带来的副本（`status.copy`）、原生会话目录没了（`status.native.blocking`：missing / ambiguous / elsewhere，除非终端里还有活的窗格握着它）都不选；还没有状态的当作可以，让服务端来拒。`agents.forCanvas`（子图入口等也用）同样跳过失效的会话。按钮上直接写交给谁（`comments/handoffState.ts` 的 `handLabel`）：「交给 Claude Code」；同时有几个可选会话时再带上会话名（它第一条消息的主题，和标签页同名）：「交给 Claude Code · 限流的问题」；算不出目标时写「交给 Agent…」，点了弹选择器；运行中写「处理中」。发送失败时线程里留一句「没有交出去：…」和一个「换一个会话」按钮；之后一旦有 agent 答复了，这些早先的失败说明（系统消息里带 `tone` 的）在答复之前的部分折成一行灰字「之前未交出，已重新交给 Claude Code」（`collapseSuperseded`，只是不显示，消息还在文件里；答复之后才出现的失败照常显示）。**钉和线程的状态**（`pinState`，四种、四个词）：未答复（还没有 agent 的答复，失败说明不算）、处理中、**已答复**（agent 的答复是线程里最后一句，钉的角上一个绿点，线程底下写「已答复」，抽屉里写「Agent 已答复」）、已解决（人点 ✓；紫底对勾是人的，和绿点不是一回事）；已答复保持到人点 ✓ 结束线程为止，人再追问就回到未答复，再交出去就是处理中。（`Message.action: "switch-session"`，只在线程最后一条、且没在处理时出现）：点它打开选择器，选完直接把这条评论重发给选中的会话。
- **对小人说话**（`TalkBubble.tsx` `.css` `talk.ts`）：点一个小人，它旁边出一个小输入框（默认在脚下，尾巴指着它；脚下会盖住节点或连线时换到头顶气泡上方或左右，始终在可见的画布区域里，`talk.ts` 的 `placeTalk`，换边有滞后，走动时不来回跳），回车发到它的会话（`agents.send`），Esc 只关框、不取消选中（`data-esc-local`，应用的全局 Esc 不管它）。不能直接对话的（进程内子代理、Seedmux 这类外部 worker）：框里**一开始**就写「对 Pi 说（关于 Codex）…」，框下一行小灰字「Codex 是 Pi 派的，话会发给 Pi」，发出时自动在前面加「关于你派的 Codex：」，没有「改发给…」这一步（`talk.ts` 的 `talkTarget`）。发出后输入框换成一行说明：「已发给 Claude Code」；发之前那个会话正在跑一轮（`running` / `busy` / 有排队）就写「已发给 Claude Code · 会在这一轮结束后送达」（从面板发的消息要等这一轮结束）。**小人点头等消息真的送达**：`watchDelivery` 盯着会话转录，出现一条时间在发送之后、正文含这句话的用户条目才 `talk.said(收到的运行)` 并把说明改成「· 已送达」（约 4 秒后关框），动画那边读 `talk.get()`（`{ runId, at }`，墙上时钟）让那个小人转身点头。这条消息在会话面板里就是一条「来自 Agora」的用户消息（`TrajectoryView`）。**干活时也能说**：占位文字是「对 Claude Code 说…（这一轮结束后送达）」，发出后按 `sendState` 写「已发给 Claude Code · 会在这一轮结束后送达」，送达后「已送达」并点头。**在哪都能说，页面上只有一个框**：主画布和跟随标签的叠层都挂 `<TalkBubble>`（`Overlay.tsx`），每个视图每帧报告自己是否画着被选中的小人（`figurePositions`，没画就删掉），`pickTalkHost` 选出承载框的那一个（原来的留着；主画布优先于跟随标签），只有它渲染，没有藏着却占焦点的框；小人哪个视图都没画（在子图里又没开跟随）就没有框。发给会话时跟随标签的视图 id（`follow:<画布>`）换回真正的画布。

## 13. 新想法（试验）

每项独立，先挂上看效果，不要就整项删掉（文件 + 下面写明的挂载行 / 开关）。全部从运行数据算，不另存状态。挂载的几行已接进叠层、时间线和 App；证据在 round-01 的 `evidence/ideas/`、`evidence/p10/`。

**1. 脚印**（`trail.ts` `footprints.ts` `FootprintLayer.tsx`）：节点上沿画一串很淡的紫色脚印点（左右脚交替、往右渐淡），站过、写过越久越多越深（最忙的节点 12 个点、透明度 0.38，其余按密度，至少 2 个）。「站过」读自 `stateAt`（`trail.ts`：每段工作站在哪、每次走到哪），所以和画面一致——短读只看不走，思考、等你算在站着的地方；闲着逗留、走路、图外托盘、只有回执的 worker 都不算；写的时间算两遍（写是图上唯一用紫色的动作）。范围是页面上已有的全部运行，回放时只算到播放头；随运行刷新（有人干活时每秒一次）或回放（≤4 Hz）重算，不进帧循环。⋯ →「小人的脚印」可关（`prefs.footprints`，默认开；工位视图关着时也不画）。挂载：`Overlay.tsx` 世界坐标组 `<g ref={svgWorld}>` 的第一个子元素 `<FootprintLayer ctx={ctx} boxOf={geom.boxOf} />`。

**2. 今日小结**（`summary.ts` `DaySummary.tsx` `.css`）：今天 0 点到现在（回放时到播放头）：几个 agent（其中几个子代理）、走了几步（从一个节点走到另一个，交回时走回派它的人也算）、改了几个文件（写过的不同文件）、跑了几次命令、等了你多久（两个人同时等只算一次）、最忙的节点（站着干活最久）。线条卡片，紫色图标，等你的时长用暖色。挂载（`Timeline.tsx` 细条右边的计数）：`const [dayAt, setDayAt] = useState<HTMLElement | null>(null);`，`<span className="ws-cnt" onPointerEnter={(e) => setDayAt(e.currentTarget)} onPointerLeave={() => setDayAt(null)} …>`，再加 `{dayAt && canvasId && <DaySummary canvasId={canvasId} anchor={dayAt} />}`（卡片自己用 portal 摆在它上方、右对齐，不接指针）。

**3. 对小人说话**：已转正，见 §12。

**4. 延时片段**（`web/scripts/clip.ts`）：`node scripts/clip.ts <url> <out.mp4|out.gif> [--from <t>] [--to <t>] [--speed 8] [--dark]`。`<t>` 可以是第一次活动之后的秒数、当天的 `HH:MM[:SS]` 或 ISO 时间；默认从第一次活动到现在，`--to` 还没到就等（`?mock=runs` 的脚本从打开页面起实时演 46 秒）。做法：Playwright 打开页面，在细条上按空格进时间线自己的回放（带它的空闲段），再让页面自己的 `clock` 按倍速播这一段——空闲照样跳过；录整页，ffmpeg 切出这一段、裁到画布、出 MP4 或 GIF。录的时候不热更新（按住 Vite 的 HMR 连接），也不写项目（除 GET 之外的 `/api` 请求一律拒绝，页面自己的 workspace 自动保存也不例外）。要开发服务器（要拿到页面的 clock 模块）。

**5. 测试结果上屏**（`outcome.ts`，只有纯函数）：拿得到。服务端每个 CLI 的适配器都把成败写进条目的 `tool.isError`（Claude `is_error`，Codex 退出码 ≠ 0 或状态 failed，Pi `isError`，Grok 退出码），没跑完时没有这个字段；页面拿到的输出只有前 4000 个字（`outputLen` 是全长）。`execResult(item)` 给 `{ ok, passed?, failed? }`：成败只信 `isError`；输出完整时再从最后一行测试汇总里读通过 / 失败数（pytest、vitest、jest、cargo、mocha），被截断就只给成败；没跑完或旧快照没有 `isError` 给 null（不猜）。`execResults(run, items)` 按片段给出一个运行的全部结果。显示建议：终端道具在这段命令结束后亮 700 ms（✓ 用 `--positive-dot`，✗ 用 `--negative`）；泳道里执行片段右端上方一个 7 px 的小圆标（✗ 实心 `--negative`，✓ 空心 `--positive`），悬停卡片写「通过 3 · 失败 1」。限制：只有顶层运行的条目在页面上（`agents.get().items[sessionId]`）；子代理的条目在 `runs/derive.ts` 的 `fromTree` 里用一次就丢了。要子代理也有 ✓ / ✗：在 `lanes.ts` 的 `buildLane` 里把 `ok: !it.tool.isError`（有这个字段时）带进片段、`toRunSeg` 照抄，结果随片段走、`execResults` 就不需要了；服务端不带条目的 `timeline.segments` 也要补同一个字段。

**6. 图外文件提示补节点**（`unmapped.ts` `TrayHint.tsx` `.css`）：agent 写过、但图上没有节点认领的文件（写的时候小人站在图外托盘上），按最近的公共目录分组，同一个目录超过 2 个就在托盘里有一行「server/cache/ 有 3 个新文件，要画进图里吗？」——**只在鼠标移到托盘上时出现**（页面不自己冒东西；行的位置一直留着，不会挤动托盘）（更深的目录先认领，一个文件只算一次；读过的、项目根目录下的不算——读 docs/ 不是改图的理由）。点它只复制这句话和文件清单，去评论或会话里粘贴，不改图。没有直接填进输入框：会话输入框只在打开时读一次 `draftText`，已经开着就会丢。挂载：`Overlay.tsx` 的 `.ws-tray` 里、两行说明之后 `<TrayHint locate={geom.locate} />`。

**7. 等你就叫你**（`notify.ts` `WaitNotifier.tsx` `attention.ts`）：页面不在前台时，有 agent 开始等你（在页面切走之后开始、此刻还在等），就发一条系统通知「Pi 在等你：POST /users 要不要登录才能调？」（子代理写「Codex（Pi 派）在等你回复」），同一段等你只发一次；点通知回到页面。页面回到前台时 `attention.ping()`：动画那边读 `attention.get()`（`{ at }`）让等你的小人朝你挥手。⋯ →「等你时通知我」（`prefs.notifyWait`，默认关），打开时在这次点击里向浏览器要权限，被拒就保持关并写「浏览器已拦截」。它直接订阅运行数据和页面可见性，后台标签页不靠 React 渲染也能发。挂载：`App.tsx` 里一次 `<WaitNotifier />`。

删掉某一项：删上面列的文件和它的挂载行；1 和 7 还要删 `prefs.ts` 里对应的字段、`ViewMenu.tsx` 里那一个开关（7 连同 `WaitNotifier` 的 import）；`trail.ts` 由 1 和 2 共用，两项都删时一起删。

## 14. 细条与泳道不密

导入的主会话可以跨好几天、带上百个子代理，细条和泳道不能画成条形码（`density.ts`，`density.test.ts`）。

- **细条上的活动按像素分桶**：一行的片段密到平均不足 8 px 一段时，不再一段一段画，改成每约 3 px 一个桶、每桶一条，颜色深浅是这个桶被占用的比例。稀疏的行（例如 `?mock=runs` 的 5 个 agent）照旧一段一段画。
- **子代理只列 8 个**：一个运行的子代理超过 8 个时，展开的泳道只列此刻（回放时是播放头）附近最近活跃的 8 个，其余收成一行「+N 个子代理 ▸」，点开再展开全部。
- **都空闲太久**：所有会话（子代理算在内）都结束超过 10 分钟，且不在回放，细条只写「都空闲 · 上次活动 <日期 时间>」，不画活动条。

## 15. 窄窗口里的「浏览 / 评论」条

窗口窄、画布不到约 730 px 宽时 Excalidraw 切到紧凑布局（底部一条带菜单和撤销的栏，右边一条竖工具栏）。「浏览 / 评论」条这时放进那条底栏的空的中间（`canvas/dockPlace.ts` 的 `isCompact` / `dockBottom`，`App.tsx` 量底栏里的 `.Island` 取位置），不压在图上也不压在栏的按钮上；宽窗口里照旧在画布底边上方一点。
