# 工位视图：agent 在图上干活，时间线能回放

每个 agent（一个会话，以及它派出去的子代理）是图上的一个小人：它读写哪个节点的代码，就走到哪个节点上站着干活。**小人就是指针**——原来的进度指针胶囊、节点紫底都去掉了。下方一条 34px 的活动细条随时在，拖动它就回放；展开是按 agent 分的泳道。

- 默认打开，⋯ →「工位视图（小人）」可以关（本浏览器 `localStorage` 的 `agora.workstation.v2`）；关掉后每个 agent 在它的节点上是一个紧凑的在场胶囊（头像 · 名字 · 在做什么 · +N）。
- 设计稿：`workbench-focus/index.html` 的状态 a–e（本轮实现）和 f–j（v2，见 §9）；原型：`workstation-proto/`。灵感来自 Loom Studio（loom-studio-sep-2026.moldandyeast.com：程序化小人、按人分泳道、拖动回放）。只参考它公开描述的技术，没有用它的任何代码。

## 1. 数据

- **运行**：顶层是 Agora 会话；子代理是它派出去的（Claude Task / Agent 工具、Codex spawn、经 Seedmux 的 worker），再往下不限层数。服务端 `/api/agent/runs?items=1` 给出每个 run 的条目（前端按和顶层一样的规则切成读、写、执行、思考、等你、派）、`moments`（父泳道上的派发 / 交接时刻）和 `receipts[]`；回执状态沿用服务端的统一状态（dispatched / acked / running / done / idle / session_changed），界面显示时把 `done` 按来源读作「声明完成」（Seedmux）或「已返回结果」（原生），`accepted` 读作「验收通过」，idle / session_changed 读作「状态不明」（`receiptView`）。
- 顶层运行从转录推（确定：同一份日志得到同一条泳道）；`runs/store.ts` 在会话有转录时取运行树，会话在跑时每 3 秒再取一次，把子代理挂到顶层运行下，父运行里派出它的那次工具调用改成「派」片段；服务端没有这个接口（404）时一分钟内不再问。
- **在场**：正在跑，或一分钟内有动静；空闲超过一分钟就淡出、离开画布（`IDLE_LEAVE_MS`），新的工作开始时出现在那段工作第一个节点上，不会从离开前的位置走过来。原来「最后聚焦的会话」永远显示的例外去掉了（它让「Pi App.tsx 10:03」挂了七小时）。

## 2. 小人

- **站在哪**：文件映射到哪个节点（和子图汇总后的有效路径同一套）就站在那个节点的上沿；子图里的文件站在父节点上，气泡里写「↘ 子图 · 订单模块」；映射不到的在图外托盘（贴着图，不在屏幕角落）。同一个节点上的沿上沿并排站（树序：子代理挨着派它的人），间距 56 屏幕像素，头和手里的东西不相碰。
- **子代理**：小一号，头是自己的 agent，头顶角标是派它的人；工作时一根虚线牵回主 agent；派出时出现在主 agent 身边（主 agent 做一个指派的手势），走到自己的文件那里，交回时走回来、转身递过去，然后淡出。只有回执的 worker 原地不动，头顶一个灰色 ?。只画一层子代理，更深的折成父气泡上的 +N（时间线里也不展开）。
- **姿态**：写（紫屏电脑，手在敲）、执行命令（石墨屏终端，按回车）、读（捧着一页纸）、思考、等你（举手 + 提示色问号）、派（指出去）、交接、空闲。头是 agent 的头像。
- **颜色**：紫 = 正在写（节点 1.5px 紫描边、电脑屏、气泡描边），以及每个区域唯一的主按钮；暖色 = 需要你（等你回复、两个 agent 同时写一个文件：节点暖描边、气泡暖底、头顶 !）；其余都是石墨色。
- **气泡**：「Pi 写 users.py 3.5 秒」「Codex · Pi 派的 · 读 users.py · 运行中」「Pi 等你回复 POST /users 要不要登录…〔去回复〕」。主 agent 总有气泡；需要你的子代理总有；其余正在干活的子代理最多 3 个（按一个主 agent 带 3–6 个子代理调的）。气泡摆放（`bubbles.ts` 的 `placeBubbles`，纯函数，≤4 Hz）：按「需要你 → 主 agent → 子代理」的顺序，依次试头顶（尾巴朝左下 / 右下）、往上抬、节点下面，每一行再往两边挪半个 / 一个气泡，取第一个不压节点、不压画上的文字和图、不压面板、也不碰已放好气泡的位置（节点和元素用网格索引）。**两个气泡永远不重叠**：放不下的子代理气泡收起来，数目记在最近一个显示着的上级气泡上（「+1」）；主 agent 和需要你的气泡一定显示，没有空位时取压住画面最少、但仍不碰别的气泡的位置。两次摆放之间气泡跟着走路的小人移动或滑向新位置，逐帧检查：碰到优先级更高的气泡时立即隐去、靠近 12 px 内快速淡出，离开后 120 ms 淡回。
- 点小人或气泡选中它（出「打开会话」），双击打开会话。

## 3. 时间线

- **细条（34px）**：左边一句话（「● Pi 写 users.py」「Pi 在等你回复」「都空闲 · 最后 Codex 写 app.md · 19:26:37」），中间是最多三个主 agent 的活动条（一块 canvas，逐帧画），右边是头像和「2 个会话 · 3 个子代理 · ● 1 等你」。拖动活动条就回放。只有项目里一次活动都没有时才不显示。
- **展开**：每个运行一条泳道，子代理缩进在派它的人下面（可折叠），下沿一条回执带（声明完成不是绿色，验收通过是绿色，状态不明是虚线）；父泳道到子泳道有派出 / 交回的竖线；时间轴按像素自适应刻度，空闲超过 20 秒压成一段并写明空了多久（压缩段加起来不超过宽度的 40%）；图例在 ⓘ 悬停里；播放、上一步 / 下一步、倍速只在回放时出现。
- **点泳道名**：画布平滑移到那个 agent 的小人上（约 420 ms，缓出），只移这一次，不会一直跟着；你自己一拖一滚就停。悬停出「打开会话」。
- **回放**：画布一圈淡紫内框，顶部「正在回放 19:31:45 · 回到实时」；会话面板自动切到轨迹，之后发生的变灰；Esc 或拖到最右回到实时；播放跳过压缩掉的空闲，播到现在自动回到实时。

## 4. 性能（P0）

**做法**：结构和动作分开。

- React 只在数据事件和一个 4 Hz 计时器上重建叠层的结构（有哪些小人、气泡、描边）；一个 rAF 循环（`frame.ts`）只改已有节点的属性：小人的每段肢体 `setAttribute`，气泡和胶囊 `transform`，没有 innerHTML，没有每帧的 setState。原来每帧 setState 的 `useNow` 去掉了。
- 整个叠层在一个世界坐标组里，平移缩放只改这一个矩阵；视图从 Excalidraw 的 `onChange` / `onScrollChange` 直接写进 `canvas/viewport.ts`，不经过 React。
- 节点框、落脚点、裁剪区只在场景版本或面板变化时重算；气泡避让 ≤4 Hz。
- 泳道 ≤4 Hz 重建，只渲染可见的泳道；播放头逐帧只改 transform；细条是一块 canvas。
- 后台标签页：时间永远从时钟算，不按帧累加；rAF 停了有粗计时器兜底；回到前台第一帧就是对的。被别的 tab 盖住的画布不画。

**预算**：18 个 agent、500 个元素时叠层每帧 ≤ 4 ms。

**测量**：`node web/scripts/bench-overlay.ts <url> <label> --off bare`：Playwright 的 Chromium，1440×900，`?fresh&bench=18x500`（合成的 500 元素图和 18 个一直在读写的会话），CDP `Tracing.start`（`toplevel`、`devtools.timeline`、`blink.user_timing`），每个场景 5 秒：空闲（只有动画）和滚轮平移；统计渲染主线程上顶层 `RunTask` 的时长 ÷ 60 Hz 帧数，叠层的开销 = 开着减去没有叠层（`&bare`）。结果在 `web/evidence/focus/perf/`。

| | fps | 主线程 / 帧（空闲） | 主线程 / 帧（平移） | 叠层开销 |
|---|---|---|---|---|
| 改之前（12f78eb，工位视图开） | 4.6 | 238 ms（每实际帧） | 168 ms | 渲染进程跑十几秒会崩 |
| P0 之后 | 60 | 2.31 ms | 3.47 ms | 1.8 / 2.5 ms |
| P2 之后（含动效） | 60 | 3.25 ms | 3.75 ms | **3.0 / 2.7 ms**（帧任务本身 0.43 ms） |

## 5. 动效（P2）

一条原则：**什么都不跳**。

- 走路：起步前转身、步点按缓入缓出分布、身体沿路径连续滑行（脚踩实、绕着身体摆）、摆臂和上下起伏跟步子同步、微微前倾、绕开挡路的节点、到了带一点阻尼回弹。
- 姿态切换经弹簧 250–400 ms 过渡；道具淡入缩放；弹簧按墙上时钟积分（16× 回放也按人的速度过渡），只在真正跳时间（拖动、跳到某刻、回到实时、后台回来）时复位。
- 小人出现淡入、离开淡出；并排的位置和气泡的位置都用 Hermite 滑动（从静止起步、中途改目标速度也连续）；气泡 180 ms 淡入上浮、120 ms 淡出、换字交叉淡入、耗时数字等宽定宽；节点描边 300 ms 淡入淡出换色。
- 时间线：泳道片段按 transform 移动、宽度增长（250 ms 线性，衔接 4 Hz 重建），细条逐帧画，播放头逐帧外推、轴变形时从当前位置缓动到新位置；展开收起动画高度。
- 亚像素位置（`translate3d`、SVG 小数），先读尺寸再写；回放状态给 React 的更新限到 ≤4 Hz。
- 减少动效：不走路、四肢不动，但位置变化是淡出—淡入的交叉，不硬切。

**证据**：`node web/scripts/motion-capture.ts <url> web/evidence/focus/motion [--dark] [--reduced]`：`?mock=runs` 的脚本，逐帧记录 rAF 时间戳和每个小人、气泡、播放头的屏幕位置，统计掉帧、最大帧间隔、>25 ms 的卡顿、以及「这一帧的位移和上一帧相差 >2 px」的不连续（透明度低于 25% 时的交叉淡变不算）。每个场景有 MP4（浅色另有 GIF）。

## 6. 取舍

- **平面而不是轴测**：画布是用户自己画的平面架构图，斜过来会破坏图本身。
- **读也移动小人**：只看写的话小人大部分时间站着不动；「在看哪」本身有用。
- **一个主 agent 带子代理是常态**：两个顶层 agent 同时干活很少见（之后宿主会加运行锁），所以不做多顶层的拥挤规则，只保留一个兜底：同一节点并排站。
- **图外托盘贴着图**：不是屏幕角落，拖动画布时跟着图走。

## 7. 可达性

- 回放位置是 `role="slider"`，带 `aria-valuetext`；时间线聚焦后 ← → 1 秒（⇧ 5 秒），[ ] 上一步 / 下一步，空格播放，Esc 回到实时。
- 小人是带名字的按钮；泳道名字是按钮。
- `prefers-reduced-motion`：见 §5。

## 9. v2 待办（本轮不做）

用户把 v1 收到 P0–P2（外加已解决评论的规格、过时指针修复、点泳道名定位）。下面这些按设计稿做，留到 v2：

- **拥挤（P3，设计稿状态 f）**：多个顶层 agent 时每个节点最多 2 个小人、每屏 6 个，其余收成「工位组 +N」（点开展开 6 秒，有人等你时暖色边）；气泡最多 4 个；会话 tab 最多显示 2 个、其余 +N、等你的优先。v1 只保证「一个主 agent + 子代理」好看，两个顶层 agent 并排站。
- **子图（P3，状态 g）**：子图入口上显示里面 agent 的头像、有人在写时一圈淡紫；v1 只有气泡里的「↘ 子图 · X」。从不自动跳进子图。
- **跟随窗格（P4，状态 h）**：在窗口管理器里加跟随组类型、钉住、最近使用时间、4 窗格上限和替换最久没用的未钉住窗格（带撤销）；跟随窗格是画布的只读 SVG 快照加我们的叠层，一键换成可操作的画布，跟着 agent 自动进出子图，你的视图不动。泳道名 / 小人 / 树行一键跟随，「跟随中」标记，F 键，Esc 先退追踪再退跟随，跟随的泳道置顶，agent 结束后窗格停在最后位置并写「已结束 · 停止跟随」。v1 的「点泳道名」只是把主画布平滑移到小人上一次。
- **Agent 树与追踪（P5，状态 i、j）**：树面板（全部 / 运行中 / 等你 / 出问题，行悬停追踪 / 跟随）；追踪时其余变淡、按到访顺序编号的路线站点和子图传送点、子代理从派出站到交回站的细虚线、时间线只剩它和它的子代理、拖动时沿路线走、Esc 退出；追踪和跟随可以同时开。
