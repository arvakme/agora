# 工位视图：agent 在图上干活，时间线能回放

每个 agent（一个会话，以及它派出去的子代理）是图上的一个小人：它读写哪个节点的代码，就走到哪个节点上站着干活。**小人就是指针**。默认只有两样：左边的架构图（在哪儿做）、右边的对话加轨迹（做了什么、做到哪）。原来的底部细条和泳道已经去掉（§3）；顶栏右侧一排 agent 小标签说谁在干什么。

- 默认打开，⋯ →「工位视图（小人）」可以关（本浏览器 `localStorage` 的 `agora.workstation.v2`）；关掉后每个 agent 在它的节点上是一个紧凑的在场胶囊（头像 · 名字 · 在做什么 · +N）。
- 设计稿：`workbench-focus/index.html` 的状态 a–e（本轮实现）和 f–j（v2，见 §9）；原型：`workstation-proto/`。灵感来自 Loom Studio（loom-studio-sep-2026.moldandyeast.com：程序化小人、按人分泳道、拖动回放）。只参考它公开描述的技术，没有用它的任何代码。

## 1. 数据

- **运行**：顶层是 Agora 会话；子代理是它派出去的（Claude Task / Agent 工具、Codex spawn），再往下不限层数。服务端 `/api/agent/runs?items=1` 给出每个 run 的条目（前端按和顶层一样的规则切成读、写、执行、思考、等你、派）、`moments`（父泳道上的派发 / 交接时刻）和 `receipts[]`；回执状态沿用服务端的统一状态（dispatched / acked / running / done / idle / session_changed），界面显示时把 `done` 读作「已返回结果」，`accepted` 读作「验收通过」，idle / session_changed 读作「状态不明」（`receiptView`）。
- 顶层运行从转录推（确定：同一份日志得到同一条泳道）；`runs/store.ts` 在会话有转录时取运行树，会话在跑时每 3 秒再取一次，把子代理挂到顶层运行下，父运行里派出它的那次工具调用改成「派」片段；服务端没有这个接口（404）时一分钟内不再问。
- **在场**：正在跑，或一分钟内有动静；空闲超过一分钟就淡出、离开画布（`IDLE_LEAVE_MS`），新的工作开始时出现在离开前站的地方（第一次是图外托盘；那段工作的第一个调用就有位置时直接出现在那里），再走到工作的节点或切镜（§17）；一轮还在跑时不因没有调用而离场。原来「最后聚焦的会话」永远显示的例外去掉了（它让「Pi App.tsx 10:03」挂了七小时）。

## 2. 小人

- **站在哪**：文件映射到哪个节点（和子图汇总后的有效路径同一套）就站在那个节点的上沿；节点按它看起来的范围算（素材库图标是整组，连同下面的名字）。子图里的文件站在父节点上，气泡里写「↘ 子图 · 订单模块」；映射不到的在图外托盘（放在图里最下面的东西右边，和原型一样，放不下再放左边或图下方；托盘和站在上面的小人都不压东西）。工位按原型的 `dockPoint`：从上沿左端进来 24 px，每人 46 px 起、按小人画出的实际宽度加宽（100% 时小人画成 1.2 倍，间距 54 px），可以沿上沿往右伸出两位；每个工位都要让站着的小人（连头顶的 ! / ?）不压别的文字、图标、箭头标签，节点自己的部分不算；上沿站不下时依次用右侧、左侧（站在节点底线上）、下方（`docks.ts` 的 `dockSpots`）。同一个节点上按树序排（子代理挨着派它的人），位置变化用 Hermite 滑过去。
- **出场与切镜（导演层，§17）**：一段工作开始时，小人出现在它上次站的地方（第一次是图外托盘；第一个调用就有位置时直接出现在那里），再走到第一个调用的节点；那一步超过 650 个世界单位就不走，改成切镜——旧位置淡出、新位置淡入 300 ms，两处透明度之和为 1。不再用「还没发生的调用」决定出场位置。
- **智能体改图（FX3）**：真实 Claude 用 `agora canvas apply | anim | child` 改图时，命令在页面里执行（`session/agentBridge.ts`），页面知道改了哪些节点、什么时候——所以由页面执行器直接告诉工位视图（`touches.record`，不解析日志），`runs/touch.ts` 把它合成进那个会话的 run：每一「片」是一段 `write`，`path` 是被改节点（`runs/nodePath.ts` 的 `nodePath(画布, 节点)`；`geometry.ts` 的 `locate`、`subview.ts` 的 `levelsOf` 认它，节点在子图里就站在开子图的节点上、走门下去）。一次改很多节点不是 30 个节点走 30 趟：够得着（`REACH_PX` 420，回放的精简同一个常量）的节点是一片、站着画，片按画的顺序、就近走；下一站走得动（估计 ≤ 4 秒，按回放的走速 220 px/s 加绕路）就走过去，否则 `RunSeg.cut` 切镜；整段最多 `BUDGET_MS` 8 秒（改动自己有时长时取它的 1.5 倍），放不下的站直接到位，不压短每一站（压短会让小人追赶、丢站、速度突变）；图上的事实永远先出现。触发命令自己（`agora canvas …` 的 exec）在写开始处让位，不再显示成小人的一次「跑命令」。同一个改动重复通知只算一次；页面没有对应会话就忽略；节点已被删掉时小人留在原地。减少动效：不走不切，只到位。评论智能体（「交给 X」）的小人也不再直接出现在钉子上：一段从评论开始、没有文件的工作，从托盘（或它上次站的地方）走到钉子。
- **走法（剖面）**：把图当剖面看：节点上沿是台面。换节点时沿两端都绑在节点上的箭头走（最短的一串，按正交长度算）——横着的一段是桥，竖着的一段是梯子（立在箭头竖直那段；没有竖段就在间隙正中；上下叠着的两个节点，梯子在上面那个的侧壁外 10 px）；没有箭头相连、或那条路会穿过节点，就从近处的角搭临时脚手架，越过中间最高的东西 24 px 再下来；去图外托盘总是走脚手架（`route.ts`）。进出子图也是爬梯子：在入口节点的台面上开一个口，顺梯子往下一个小人高，身子被台面线裁掉（§12）。桥和梯子只在走的时候画：桥是腿高度处一条虚线加两端小立柱，梯子是两根竖杆加横档（横档就是手脚踩的地方），脚手架的更淡、虚线，选中的小人的是紫色；行程开始时 200 ms 淡入，到达后 300 ms 淡出。两个台面高差不到 12 px 算「台阶」：不画梯子，脚落到新高度，身体随之上下。走的时候并排的站位偏移滑到 0（小人始终在桥 / 梯子上），到了再滑回自己的工位。
- **短读只看**：读别的节点的文件，是**一次**真实时长不到 2.5 秒的读、紧接着在同一节点上没有别的活（没有再读、写或跑命令），就不走过去——小人留在原地、做「读」的姿态、转向那个节点，从头部到那个节点上沿中点一条紫色虚线，那个节点描 1.2px 紫虚线框（「在读」，看的是图外托盘时托盘也显示出来）。2.5 秒及以上、接着在那里再读 / 写 / 跑命令（同一节点上连着读几个文件就是在那里干活，每个再短也走过去）、或这次读的时长是补出来的（派出去的 Codex 的命令开始和结束是同一刻，段落补成固定长度，`durationKnown: false`，不算短读），才在读开始时走过去（`place.ts` 的 `GLANCE_MS`）。
- **子代理**：小一号，头是自己的 agent，头顶角标是派它的人；工作时一根虚线牵回主 agent；派出时出现在主 agent 身边（主 agent 做一个指派的手势），走到自己的文件那里，交回时走回来、转身递过去，然后淡出。只有回执的 worker 原地不动，头顶一个灰色 ?。只画一层子代理，更深的折成父气泡上的 +N（时间线里也不展开）。
- **姿态**：分两层（§16「姿势分层」）。底层是站 / 走 / 爬；空闲（和只有回执的 worker）就是**双手背后**的站姿：两手背在身后、身体略前倾 3°、腿放松伸直（膝盖只有一点点弯）、两脚分开 7.2 单位，有呼吸（髋上下 0.2 单位）、偶尔重心微移（身体左右 0.45 单位）、每隔九秒左右转头看一眼（约一秒）。上层是在做的事：写（紫屏电脑，手在敲）、执行命令（石墨屏终端，按回车）、读（捧着一页纸）、思考、等你（举手 + 提示色问号）、派（指出去）、交接。进出上层逐步混合 0.28 秒：从站姿进入先「起势」（手从背后拿出来举到胸前），做完「收势」（两手拍一下），再回到背后。头是 agent 的头像。
- **颜色**：紫 = 正在写（节点 1.6px 紫描边、电脑屏、气泡描边），以及每个区域唯一的主按钮；暖色 = 需要你（等你回复、两个 agent 同时写一个文件：节点暖描边、气泡暖底、头顶 !）；其余都是石墨色。
- **气泡**：原型的写法和样式（动词图标、完整路径、「Codex Pi 派的 读 server/users.py 2.4 秒 运行中」「Pi 等你回复 POST /users 要不要登录才能调？〔去回复〕」「Claude Code ✓ 空闲 这一轮做完了」、子代理验收后父气泡上 2.5 秒的「Codex 验收通过」）。主 agent 总有气泡（空闲的也有）；需要你的子代理总有；其余正在干活的子代理（写的优先）补到子代理气泡共 3 个为止。摆放（`bubbles.ts` 的 `placeBubbles`，纯函数，≤4 Hz）按「需要你 → 主 agent → 子代理」：**气泡属于它的小人**——先试原型的位置（`protoSpot`：一个人时在脚左 20 px、头线上 34 px，尾巴指着它，走路时也一样；同一节点几个人时从第一个工位往上每 34 px 叠一个，不带尾巴，靠左边的头像认人）；不行就在头顶左右滑（尾巴始终指着自己的头，两个并排的人各往外伸）、抬一行（细竖线连到头）、或贴在头旁边（侧尾巴）；都放不下时**收成头顶的小签**（动词图标 + 一两个字：读 / 写 / 跑 / 想 / 等你 / 闲 / 走 / 派 / 交 / ?），不会跑到远处。气泡不压节点、文字、图标、箭头标签和站着的别的小人（选中的气泡除外），**两个气泡永远不重叠**（说话框也躲开所有在场的气泡，见 §12）；**一个气泡最宽 260 px**（`bubbles.ts` 的 `BUBBLE_MAX_W`，CSS 里 `--bub-max` 同一个数；选中的那个在话的右边多两个按钮的宽度，最宽约 370 px）：路径、命令、地点、一步的说明、问你的问题这些长的部分分摊余下的宽度、末尾用 … 收住，鼠标放上去这个气泡就展开成完整的话；靠近窗格左右边缘时尾巴在气泡上滑动（离左右缘至少 8 px），整个气泡留在窗格内，滑不动就换到头旁边或收成小签；连小签都放不下的子代理才收成上级气泡上的「+N」。气泡锚在小人的脚上（转身、点头不带着它晃），两次摆放之间跟着走路的小人移动或滑向新位置（长距离滑得更久，起停加速度都不超过 2000 px/s²）；逐帧检查：碰到优先级更高的气泡立即隐去、贴近 2 px 内快速淡出，离开后 120 ms 淡回。
  **选中小人的气泡里各部分互不压字（FX6）**：气泡最宽 260（`--bub-max`），选中时按钮（打开会话、跟随）另在文字右边、隔 6px；里面的字按等级让位：先是标题（智能体名 · 会话名，`.who`，最先省略，`text-overflow: ellipsis`），再是警告、计时、路径，**状态字（「思考」「读文件」「等你回复」…）、图标、头像和按钮永不缩**（以前没有给 `.who` 规则，总宽超出后状态字被右边的按钮盖住，读成「思考打开会话」）。用真的长会话名和各种状态字、1440 宽和 1000 宽各测过，气泡里所有子元素的框两两不相交（`round-06/evidence/FX6/probe.mjs`），CSS 规则由 `bubbleCss.test.ts` 守着。说话框（「对 Claude Code 说…」）现在也躲开**别的小人**（把它们的 `.ws-hit` 框当障碍，`TalkBubble.tsx`），不再盖在邻居的头上；它没躲图上的连线（连线是折线/斜线，包围盒很大，全当障碍会没地方放），所以仍可能有线从它下面穿过。
- **节点描边**（原型）：有人在写 1.6px 紫，等你 1.6px 暖色，在读 1.2px 紫虚线，其他在干活 1.4px 灰，两人同时写同一文件 2px 暖色宽框；时间线上悬停 / 选中一段时框出它的节点（虚线 / 实线紫）。空闲的小人 62% 不透明。
- 点小人或气泡选中它（出「打开会话」），双击打开会话。

## 3. 右侧：agent 小标签、轨迹和按轮回放（底部细条已去掉）

用户的话：「右边的轨迹不会跟着动，或者都这样了，还需要底部这里的时间线吗？直接都放在右侧可能比较好」。决定：默认只有两样——左边架构图（在哪儿做）、右边对话加轨迹（做了什么、做到哪）；底部细条、泳道、整个工作区按时间拖动的全局回放都去掉；按轮 ▶ 回放和镜头动画保留。细条上每样东西的去向：

| 原来在细条 / 泳道上 | 现在 |
|---|---|
| 一行状态（工位 · agent · 状态 · N 个会话 · N 个子代理） | 顶栏右侧的 agent 小标签（下面）；子代理数写在标签上 |
| 多 agent 泳道 | 去掉；子代理列在轨迹里派它的那一轮下面 |
| 回放控制（播放、暂停、倍速、拖动、回到实时） | ▶ 回放一轮时显示在轨迹顶部：暂停 / 继续、.5 1 2 4 倍速、退出（Esc 也退出）；全局拖动去掉 |
| 段的详情卡、「回放到这里」 | 去掉；轨迹的行就是详情 |
| 「新建会话」 | 会话标签行的「+」和空会话面板 |
| 「等你」 | agent 标签上的「等你」，加图上的小人（问你的气泡） |
| 点泳道名：移到小人、追踪 | 点小人选中它（出说话框）；点小标签打开那个会话；点轨迹里的子代理让镜头跟着它（§10） |
| 今日小结、活动条、图外托盘提示入口 | 今日小结和活动条去掉（没有入口）；托盘提示留在画布叠层里（`TrayHint.tsx`，悬停才出） |

- **agent 小标签**（`session/AgentTagRow.tsx`，排序与筛选在 `agentTags.ts`）：顶栏右侧、分享按钮左边，每个顶层会话一个：头像、名字、状态（干活中 / 在想 / 等你 / 空闲）、子代理数（「+N」）。「在干活」就是镜头用的那一条标准（`liveCamera.ts` 的 `isWorking`）：一轮在跑，或有一个调用正在进行；干活里再分：问着你的话是「等你」，思考或两次调用之间是「在想」，其余「干活中」。排序：干活中、等你、在想，然后最近空闲的；放不下的收成「+N」（点开是列表）。点标签切到那个会话的标签页，没开就打开；悬停写状态、在做什么、在哪个节点、子代理数。窄窗口里只留头像和名字。
- **▶ 回放一轮时轨迹跟着走**：右侧切到轨迹视图（回放结束，回到原来的视图，`session/replayStep.ts` 的 `panelPlays`）；**右侧只看这一轮**：其他轮收起并变淡（`session/replayScope.ts` 的 `turnOpen`，只是画法，你自己收起、展开的记录不动，回放结束原样回来），这一轮的标题滚到顶部；当前这一步（回放位置之前最后一行，`currentRecord`）平滑滚到视野中间，高亮是左侧一条进度线沿边长下来加底色淡入（`trajectory.css`，减少动效时不过渡）；之后的行变淡。只有你**真的**滚动（滚轮、触摸、翻页键，`session/followModel.ts` 的 `isUserScroll`）才停止跟随，出胶囊「回到当前步」，点了回到跟随；程序自己的滚动、面板切到轨迹视图、开始前触控板还没停的惯性滚动（开始后约 0.9 秒内的滚轮 / 触摸）、按钮上的空格 / 回车都不算，所以一开始不会出现「回到当前步」；进行中的轮不再往底部滚（「回到最新」让位给它）。轨迹顶部是播放控制（`session/PlayControls.tsx`，按的是 `clock.pause / play / speed` 和 `plays.exit`）。回放不在的时候这些都不出现。
- **子代理挂在派它的那一轮下面**（`session/subAgents.ts` 的 `kidsByTurn`）：轨迹里一轮派出的子代理列在这一轮末尾：名字、状态（运行中 / 已返回结果 / 声明完成 …）、用时；点它让镜头跟着它（`liveFollow.follow`）。挂到哪一轮：先看派它的那次「派」调用所在的轮；没有（Seedmux worker 只有回执）就看它派出时刻之前最近开始的那一轮，早于第一轮的不挂。Claude 的 Task、Codex 的协作子代理、Seedmux worker 都算。
- **回放只有一种进入方式**：轨迹里的「▶」（或对话里一轮头部的 ▶）；单击、悬停都不回放。回放中画布一圈淡紫内框、顶部一个不带按钮的小标注「回放中 · 第 N 轮」（`ReplayBar.tsx`；暂停、倍速、退出在右侧轨迹顶部，Esc 也退出）；Esc 或播完汇总后自己回到实时。


## 4. 性能（P0）

**做法**：结构和动作分开。

- React 只在数据事件和一个 4 Hz 计时器上重建叠层的结构（有哪些小人、气泡、描边）；一个 rAF 循环（`frame.ts`）只改已有节点的属性：小人的每段肢体 `setAttribute`，气泡和胶囊 `transform`，没有 innerHTML，没有每帧的 setState。原来每帧 setState 的 `useNow` 去掉了。
- 整个叠层在一个世界坐标组里，平移缩放只改这一个矩阵；视图从 Excalidraw 的 `onChange` / `onScrollChange` 直接写进 `canvas/viewport.ts`，不经过 React。
- 节点框、落脚点、裁剪区只在场景版本或面板变化时重算；气泡避让 ≤4 Hz。
- 没有时间线了：回放只有「按轮 ▶」（§11），播放头由 `clock.ts` 按墙上时钟算；轨迹里当前行、小标签的状态都是 ≤4 Hz 的 React 更新，不逐帧。
- 后台标签页：时间永远从时钟算，不按帧累加；rAF 停了有粗计时器兜底；回到前台第一帧就是对的。被别的 tab 盖住的画布不画。

**预算**：18 个 agent、500 个元素时叠层每帧 ≤ 4 ms。

**测量**：`node web/scripts/bench-overlay.ts <url> <label> --off bare`：Playwright 的 Chromium，1440×900，`?fresh&bench=18x500`（合成的 500 元素图和 18 个一直在读写的会话），CDP `Tracing.start`（`toplevel`、`devtools.timeline`、`blink.user_timing`），每个场景 5 秒：空闲（只有动画）和滚轮平移；统计渲染主线程上顶层 `RunTask` 的时长 ÷ 60 Hz 帧数，叠层的开销 = 开着减去没有叠层（`&bare`）。结果在 `web/evidence/focus/perf/`（保真对照那次在 `web/evidence/fidelity/perf/`）。

## 5. 动效（P2）

一条原则：**什么都不跳**。

- 走路（台面、桥、台阶）：起步前转身；远侧脚先迈，等长的步子，每步落在身体前半步、抬起时在身体后半步，最后一步落到工位、另一只脚跟上；身体沿路线连续滑行——加速、匀速、减速三段，速度连续；摆臂跟对侧脚、上下起伏跟步子、微微前倾；过台阶时身体在台阶前后一段里平滑升降；到了带一点阻尼回弹。
- 爬梯：走到梯子跟前（不停，见下）离梯子 4 个小人单位、面向梯子（从哪边来就站在哪边）；手脚在走路减速的最后一段和爬梯起步的第一段里（各不超过 150 ms）上梯，身体不停顿、速度连续（拐角速度见下）。梯子上躯干直立略朝梯子、膝盖弯，手脚都踩在横档上（**下梯**：手脚一次只挪原来的一半——四档改两档——、髋留在站高的 0.9 倍而不是 0.8 倍、手比脚线靠前 2.5 单位、躯干再朝梯子多倾 6°，髋随之前移到脚线上方（最多 3 单位、离脚线 0.8 单位内为止），不再像坐在梯子上：髋在脚后面、两个膝盖折起、身体直立；**门的梯子**下行髋只留到 0.835，再高，头在门关上那一刻还有一点露在台面线上）：对角成对（近侧手 + 远侧脚、远侧手 + 近侧脚）轮流移动，一对移动时另一对抓牢，身体连续上下；到顶跨上台面、到底踩到台面，手离开梯子后再转身往前走。横档约 5.5 个小人单位（× 小人比例，按梯子高度均分），竖杆高出上层台面约 22 单位当扶手。
- 时长与步速（2026-09-29 用户决定调慢走路，原先整趟夹在 0.7–2.4 秒、远路被压到约 600 px/s，看起来像在跑）：走路步速顶到 0.22 px/ms（每秒 220 px，一步约 5 帧）、爬梯 0.13 px/ms（这是主 agent 的；子代理按比例小 0.8 倍，步子的节拍不变）。整趟的速度曲线是连续的（DR4）：只有整趟的头和尾是静止的，中间走 ↔ 爬的交界不再停：走到梯子前减速到爬梯速度的 0.6 倍（`CORNER`）、从那个速度接着爬，爬完再从它加速走（原先每段从静止到静止，走 ↔ 爬交界降到 0，70 秒里 44 次）；这个拐角（身体从横着变竖着）用一段平滑修正圆掉（`ROUND_MS` 140 ms，身体最多在拐角里面几像素，别处的路径不变），速度不会一帧转向。每段按加速度上限 `ACCEL` = 0.0008 px/ms²（× 小人比例）规划：从入口速度加到步速（或短路的峰值）、匀速、减到出口速度（`rig.ts` 的 `natural`、`fitProfile`、`Profile`），60 fps 时一帧的速度变化不到 0.02 px，实测整趟最大 1070 px/s²（要求 ≤ 1200）。所以一段路的时间 = 长度 ÷ 步速 + 起步、收步各约 0.14 秒的加减速（步速 ÷ 加速度 ÷ 2）；远路和近路迈的是同样的步子，不再越远越快；整趟（含起步转身 0.24 秒）**没有上限**，下限 0.7 秒（更短的整体放慢，步子变小）。比改前快 1%–10%（3440 → 3072 ms 等，`pose-check --speed`）。摆动脚每帧最多移动 12 px，一次迈步不少于 4 帧（`trip.test.ts` 锁定）。回放里行程跟着时间线走：慢放（`clock.motionScale`）照旧生效。
- 下一段工作在小人还没走到时就开始：**走到再出发**（`place.ts` 的 `step`）。新的一趟从上一趟的终点、上一趟到达的那一刻起，接着走，位置始终连续，不会瞬移，也不会半路折回；等的这段时间里它继续走完上一趟，新工作的姿势（写、读…）在它出发走到新节点之后才开始。这条规则对回放和实时一样（纯函数：新一趟的开始时刻 = max(那段工作的开始时刻, 上一趟的到达时刻)）。
- **门的两边同一时刻**（`place.ts` 的 `door.enter` / `door.leave`、`doorTiming`；`subview.ts` 的 `outer`）：走路调慢后走到门口要几秒，所以子图那张画布上的小人不再按工作段开始时刻出现，而是主画布上它**顺梯子下完（`doorsIn` + DOOR_MS，`portalPhase` 变成 `behind`）的那一刻**才在入口上方顺梯子爬下来、再走到目标节点；出门反过来：子图里走到入口、爬上梯子出了画面之后，主画布上才从口里爬上来。要同一时刻才成立，还有两条：要做的活就在入口节点自己身上（回到入口自己的文件）时，一样等那一边的门（`place.ts` 的 `outAfter`）；小人还在走向一扇门、这时同一扇门后面又来了一段活，门照旧在走到的那一刻进，不在第二段活开始时进；进出一扇门之后，下一趟要等门走完才出发。两边各自向对方要门的时刻（子图向外层要 `enter`，外层向子图要 `leave`，且向子图要的是不带这两个函数的版本，不会互相追问）。入口小胶囊和口上的头（`presenceAt`，EntryMarks 传入主画布的上下文）也用这一刻：在门外走的时候不算"进了子图"；进了才算，出门走完才回到主画布。只用 ≤t 的数据，回放与实时一致。已知：子图深过两层时只按最近一层已发布的画布对时；跟随窗口的自动弹出每 250 ms 查一次，比主画布进门晚 ≤ 0.25 s。
- **追赶（不无限累积滞后）**：新工作段开始时，如果小人还在路上、按计划到达的时刻比这一刻晚 1.5 秒以上（`CATCH_UP_MS`），就放弃中间站，从它此刻的位置和脚的位置（不停步、不再转身停顿）直接规划去最新工作段的地点，位置连续、不瞬移；这一趟步速 1.5 倍（`BOOST`）。晚不到 1.5 秒的照旧「走到再出发」，但等了超过 1 秒才出发的那一趟同样 1.5 倍（`BOOST_AFTER_MS`）。另外，一个等着出发的中间站，如果在它出发之前又有更新的工作开始了，就直接作废（从没出发过）。同样是纯函数，回放和实时结果一致。测试：`chain.test.ts`（10 段、0.5 秒一段来回跳，任何时刻落后 ≤ 3 秒，实测最大 1.6 秒；位置每帧 < 6 px，实测 5.5 px）。已知：追赶时从路上直接转向，速度会有一次折返（位置连续、脚不跳），被放弃的中间站在「追踪」里仍会列成一站。
- 转身（起步、到了、交回时转过去递东西）：整个身体水平翻过去，经侧身，200 ms（墙上时钟，缓入缓出），实时下起步时转完才迈第一步；半路再反向就从当前的角度转回去；头像、派它的人的角标和 ! / ? 不跟着镜像；跳时间时直接朝向新方向。
- 姿态切换：「在做什么」（姿态或走路）变了，手、前倾、头的转向按上一帧屏幕上的样子混合 0.28 秒（`poses.ts` 的 `layerStep`，手沿绕肩膀的弧线混合，纯函数，不硬切）；站 → 活动多一个起势（0.3 秒：手先到胸前抬起再去做事），活动 → 站多一个收势（0.56 秒：手拍一下再回背后）；混合半路又变了就从当前的样子接着混。之后还有弹簧（手、前倾）做小的平滑；道具淡入缩放；弹簧按墙上时钟积分（16× 回放也按人的速度过渡），只在真正跳时间（拖动、跳到某刻、回到实时、后台回来）时复位。帧循环给的时间只进不退：每帧用该帧自己的时间戳，数据更新后补画的那一次沿用上一帧的时间，所以不会被误当成跳时间（弹簧复位、转身被截断）。
- 小人出现淡入、离开淡出；并排的位置和气泡的位置都用 Hermite 滑动（从静止起步、中途改目标速度也连续）；气泡 180 ms 淡入上浮、120 ms 淡出、换字交叉淡入、耗时数字等宽定宽；节点描边 300 ms 淡入淡出换色。
- 回放的动效：轨迹里当前行不做过渡，跟着回放位置换；小标签的状态点只换颜色。
- 亚像素位置（`translate3d`、SVG 小数），先读尺寸再写；回放状态给 React 的更新限到 ≤4 Hz。
- 减少动效：不走路（没有行程、不画桥梯）、四肢不动，但位置变化是淡出—淡入的交叉，不硬切；短读只看照样（原地转向、虚线）。进出子图不爬梯：在口上淡入淡出，口和露头的小人直接出现、直接消失（§12）。

**证据**：`node web/scripts/motion-capture.ts <url> web/evidence/focus/motion [--dark] [--reduced]`：`?mock=runs` 的脚本，逐帧记录 rAF 时间戳和每个小人（整体位置，取点击框；转身和四肢不在这项统计里）、气泡、播放头的屏幕位置，统计掉帧、最大帧间隔、>25 ms 的卡顿、以及「这一帧的位移和上一帧相差 >2 px」的不连续（透明度低于 25% 时的交叉淡变不算）。窗口：bridge（Claude Code 过 HTTP 桥）、ladder（Claude Code 在 API 服务旁下梯、Pi 在 SQL 竖段 x = 610 上梯）、pose、bubbles-enter、scaffold（Codex 走脚手架去图外托盘）、glance（Claude 子代理在支付服务原地看图外的 docs/payments.md）、handoff-exit、replay-scrub；窗口按时间先后录，不重叠。每个场景有 MP4 和 GIF（剖面的几个窗口裁画布区）。

## 6. 取舍

- **剖面而不是轴测**：画布是用户自己画的平面架构图，斜过来会破坏图本身。把它当剖面看（节点上沿是台面、箭头是路），小人沿用户画的连线走，图不变，桥梯只在走的时候出现；斜的箭头按正交长度算，梯子可能压住竖段上的箭头标签。原先「从空中越过方框」的走法看着像飘，删掉了。
- **读也移动小人，短读除外**：只看写的话小人大部分时间站着不动；「在看哪」本身有用。一眼就看完的读（不到 2.5 秒）走过去又走回来太闹，改成原地转向、虚线指过去。
- **一个主 agent 带子代理是常态**：两个顶层 agent 同时干活很少见（之后宿主会加运行锁），所以不做多顶层的拥挤规则，只保留一个兜底：同一节点并排站。
- **图外托盘贴着图**：不是屏幕角落，拖动画布时跟着图走。
- **不把图排成树，只把层级做成梯子**：架构多数不是树（一个 Redis 被两个服务用），图里节点的位置是人和 agent 画的，本身有意思，所以图不重排、小人沿画的线走。真正是树的是层级：每张子图只挂在一个节点下面，所以进子图就是往下爬一层。给新子图排版时才建议上游在上、下游在下（`skills/agora/references/nested.md`）。

- 回放控制（轨迹顶部）是 `role="toolbar"`，暂停 / 继续、倍速、退出都有 `aria-label`；Esc 退出回放。
- 小人是带名字的按钮；顶栏的 agent 小标签是按钮，`title` 写状态、在哪个节点、子代理数。

## 10. 跟随

一张画布、一个镜头、一次只跟一个 agent。没有单独的跟随窗口：镜头就是主画布自己的镜头，agent 顺梯子进子图时主画布切进子图（顶上有面包屑和「返回」），出门切回来。你的画布不会同时出现第二份。

| 文件 | 做什么 |
|---|---|
| `subview.ts` | 纯函数：`levelsOf` 一个文件在主画布之下的层级；`presenceAt` 一个 agent 在 t 时刻站在哪一层、从什么时候起在子视图里干活（`subview.test.ts`） |
| `followChoice.ts` | 纯函数：你选了跟谁（`choose` / `chosenRun`：换一个就替换前一个；转去别的会话、那个 run 没了就作废）和画布顶上的那一行状态（`followStatus`）（`followOne.test.ts`） |
| `replayLive.ts` `liveCamera.ts` | 实时镜头：`liveFollow.follow(run)` 改跟某个 agent，`resume()` 是「继续」；`pickFollow` 决定跟谁，`spellStep` 决定「这一轮是不是镜头要跟的」，`canvasStep` 决定显示哪张画布（进子图 / 回家） |
| `director.ts` `replayView.ts` | 镜头本身：`director.ts` 的 `cameraStep`（纯函数：限速胡萝卜 + 临界阻尼弹簧，状态每帧由调用方带回）；`replayView.ts` 只把它的输出画到画布上（§17「镜头」） |
| `EntryMarks.tsx` `entry.css` | 父图入口的头像小胶囊，挂在叠层 `.ws-layer` 里 |

- **在哪一层**：从主画布往下，节点「只经它的子图」认领一个文件（不是节点自己的路径）就下一层，到那张子图里找认领它的节点，一直到底：总架构 › API 服务 › 用户模块。子图链成环时在重复的画布处截断；子图不在了就停在指向它的节点。和 `geometry.ts` 的 `locate` 同一套判断，只是 `locate` 只下一层（小人站在父节点上，气泡写「↘ 子图 · X」）。
- **谁在子视图里**：`stateAt` 的规则不变，只把地点换成最深那层的节点，所以短读只看、子代理从派它的人身边出发和交回、空闲离场都和画布上一致。「进入」的时刻 = 它上一次去主画布上（或图外）的文件之后，第一个子视图里的文件开始的时刻；在子视图之间走、往更深走不算新的进入；只是站在那里（第一份文件之前、刚被派过去、交回中、空闲）不算在干活。
- **一次只跟一个**：默认跟你正在对话的那个会话的 agent（没有焦点会话就跟最近在干活的顶层 agent，见下面「默认跟随」）。单击小人或它的气泡（选中它）、点小人气泡里的「跟随」、选中小人按 F、点子图入口上的头像（或口上露出的头）、点轨迹里的子代理，就改跟它；换一个，前一个就不跟了。这个选择属于你当时在对话的会话：你转去别的会话，或那个 run 不在了，就回到默认。全局键在 App 层一处：Esc = `focus.escape()`（先关路线 → 再清选中），F = 跟随选中的小人；焦点在输入框或时间线里时不接。
- **顶上只有一个状态**（`followStatus`，画布顶部中间，小而安静，`ws-follow-status`；有自己的纸色底和一圈墨线框，图上的连线和标签从它下面走过也读得清，深浅色跟主题）：跟着时写「跟着 Devin」；你动了画布就变成「跟着 Devin · 已暂停」，旁边一个「继续」；它空闲或离场、或者它不在这块画布上（在另一张子图里）时整个消失。它再开始干活而暂停还在，状态又出现。「干活」用镜头同一个标准（`isWorking`）。
- **父图入口**（一个口、一个头、一个名册）：有人在某个节点的子视图里时，这个节点的台面上留着他们下去的那个**口**（`hatch.ts`）：一条深色的缝，**一个小人的头露在口上**，台面线以下裁掉；**小人只是待在子图里（空闲、在干活，不在爬）时不画立在头上的梯子杆**（`hatchVisAt` 只在它在梯子上、或马上要上下时画梯子，提前 `HATCH_IN_MS` 淡入，`hatchVisSoon` 看一眼之后的状态；口本身由 `holeVisAt` 管，一直在），空闲时头旁边有一个小字「在子图 · 空闲」（悬停的标题里有子图名）；正在下、正在上、快出来时梯子照常画；减少动效没有爬梯，只有口和头；头是谁：被追踪的那个（放过一轮、路线还在图上的），其次是被跟随的那个（都要在下面才算），都不是就是最近进去的那个（`peekerOf`）；点头就是让镜头跟它（`liveFollow.follow`）。头在小人下完梯子（`behind`）之后 0.22 s 升起，它要出来时先缩下去 0.14 s（`peekRise`，从缩到哪儿就从哪儿开始，位置连续），小人再从口里爬上来。显示路线时被追踪的小人就是这个头，不会「有路线、没小人」（被追踪的空闲超过一分钟也不离场，§11）。节点左下角的**头像小胶囊**（`EntryMarks.tsx`，三个头像，再多 +N，点头像让镜头跟它）是「名册」：口上的头已经说了这一个是谁，所以**下面只有这一个、又没有在等你时，胶囊不画**（两处不说同一件事）；下面有几位、或有人在等你时，胶囊照旧列出所有人（含露头的那位）。有人在里面写时节点外一圈淡紫（`--accent-soft`）；里面有人在等你时，入口用和别处「等你」一样的暖色（外圈换暖色、胶囊里多一个暖色圆点，悬停写「等你回复 · 名字」），你不进子图也看得到。减少动效时口和头直接出现、直接消失，只保留颜色。
- **默认跟随**（`liveCamera.ts` `replayLive.ts`，镜头本身是 `director.ts` 的 `cameraStep`，`replayView.ts` 把它推广到实时；`liveCamera.test.ts` `director.test.ts`）：页面打开后，主画布的镜头默认跟着**主 agent**——你正在对话的那个会话（`pointerFollow` 且它的标签开着）的顶层运行；没有焦点会话时，跟最近在干活的顶层运行（正在干活的优先，再看最近一次干活的时间）。**你发出消息的那一刻镜头就带过去**（不等它拿到文件、不等它走到）：这一轮开始（`isWorking`）就跟，思考、执行命令、托盘、等你都算，小人已经在视野中间时镜头不动（hold），在托盘或图外就带到托盘。镜头怎么动见 §17「镜头」：约 100% 缩放（[0.7, 1.0]，装不下也不再缩到底：保持缩放、多一次切镜），死区，限速平滑（起步和停下都缓入缓出，速度不突变），远（> 650 单位）就交叉淡变切过去；小人进子图入口、进了门的那一刻，主画布切进那张子图（`nav.go`，面包屑和「返回」都在），出门切回来，两张画面交叉淡变；减少动效时直接切、直接到位。这一轮没在干活时镜头不动，也不切画布。
  - **暂停和恢复**：你真的拖动或缩放画布（拖动超过几像素、滚轮、缩放按钮）、在画布文字框里打字编辑、打开评论（点评论工具条）、自己换到另一张画布，镜头就暂停（只是点一下选中、按 Esc 关菜单都不算）；画布顶部中间的那一行状态从「跟着 <agent>」变成「跟着 <agent> · 已暂停」，旁边一个「继续」（见下面「顶上只有一个状态」），点一下恢复。暂停不是关掉：不存，刷新页面又是默认开。暂停时你在哪张画布就停在哪张。**暂停时镜头一个字也不写视图**（`replayView.ts` 的 `frame` 一开头就看手动接管，总览、减少动效、回家都在它后面）：减少动效下跟一个远处的 agent、放一轮时你拖了画布再播到总结，界面写「已暂停」就真的不动；点「继续」后镜头才重新接手（放一轮停在总结时，继续后是总览）。放一轮是你主动要的，所以**总开关关着它也照样动**（这条不变，见「优先级」）。
  - **空的会话面板**：还没有消息时不弹窗，只写三行怎么用（在这里告诉 agent 做什么；干活时图上的小人带你看它在改哪；在图上留评论、点「交给 …」）。
  - **空画布上智能体已在干活**：这时小人层不再整块隐藏（`liveCamera.ts` 的 `hideEmptyLayer`：空画布且没人干活才隐藏，画布自己的引导语显示），小人站在托盘、镜头一发话就跟过去，空画布的提示改成「Claude 在看代码、准备画图……」（`firstDraw.ts` 的 `busyHint`），这句话放在托盘下面（`.empty-cv[data-busy]`），编辑器自己的「要移动画布…」提示让位给「跟着」小胶囊，三处文字不相交（1000×800、1440×900 用 getBoundingClientRect 测过，`round-06/evidence/FX5/layout.mjs`）；画布还没有场景时 `ctxFor` 也造一个只有托盘的图（不再返回 null 而没有取景）。
  - **跟到托盘时保留图的上下文**（`replayFollow.ts` 的 `trayShotBox`）：小人在图外托盘时，取景把图离它最近的一角/一条（离图边界最近点各 360 单位）一起框，缩到 0.7 仍装不下就只保小人在窗内，不再只剩一个孤零零的节点。图是「一大团节点 + 一个孤零零的远节点」（托盘恰好挨着那一个）时，取景的是**最大的一团**（单链聚类，间距 260 以内一团；在离托盘 `BODY_NEAR` 900 单位内的里取节点最多的，都在 900 以外就取最近的一团）：装不下时取舍是保托盘上的小人在窗内、图只露最近的一片，不为了图缩到 0.7 以下。
  - **总开关**：「⋯」菜单里「镜头跟随主 agent」，默认开，每个浏览者自己的偏好（`app/prefs.ts` 的 `followCamera`，存在浏览器里，不写进项目）。关掉后画布完全不动，回到原来的行为；镜头正带着你在子图里时关掉，画布回到你原来的那张、原来的视图（不留下镜头带你去的痕迹）。
  - **优先级**：放一轮 > 你选的 > 默认跟主 agent（`liveCamera.ts` 的 `pickFollow`）：放一轮时由放一轮的镜头接管（实时镜头先回到你的画布再让位），放完回到实时跟拍；你选了谁（下面「一次只跟一个」）镜头就跟谁；时间线在回放（不是实时）时镜头不跟。放一轮是你主动要的，所以总开关关着它也照样动。
  - **一轮做完才回去**（`liveCamera.ts` 的 `spellStep` / `canvasStep`，按时间序列测试）：镜头跟的是**这一轮**（`isWorking`：这一轮在跑，或有一次调用在进行——细条判断空闲用同一个标准），不是「手里有没有文件」：思考、托盘、等你都在跟；一轮没结束镜头不走、不回家；这一轮结束、**小人也站定**（不在走、没有切镜在淡；`director.ts` 的 `figureMoving`，`replayLive.ts` 把它并进「在跟」）约 3 秒（`HOME_AFTER_MS`）后镜头缓入缓出回到开始跟拍前你的画布和视图（太远就切过去），中途不回；小人比一轮结束晚走完时镜头一直跟到它站定；去子图/回总图要它**连续**在那里约 1 秒（`ENTER_MS`）才切；小人已经下门、在这张图上看不见了（`behind`，不论它在哪一层：子图的子图也一样，`isBehind`）就当即切进去；它从门里出来、已经站在外层那张图上了（`arrived`）也当即切回来；一个子图里连做几站，它一直在门后，镜头就一直在里面，不来回（智能体画子图时「进去一站、出来、再进去」镜头每次都跟）；页面刚打开时打开前就在干的那一轮不把画布带走，它做了新的事（或页面开了 8 秒后才第一次见到这个 run，`SPELL_FIRST_SIGHT_MS`）才跟；你选了的 agent 干活就跟；你暂停或接管过的不动；减少动效直接回去。恢复跟随时，「家」换成你当时的视图，镜头从你当时的视图接着走（`cameraResume`，不跳）：不论你把画布拖到离小人多远，继续后的第一帧不切镜，速度和缩放都连续，镜头按胡萝卜的限速平滑滑过去（`CameraState.handoff`：到离目标不到 `CUT_DISTANCE` 之前不做距离切镜；之后遇到新的远目标照常切）。**回家回到你原来的缩放**：你原来以 30% 看整张大图，回家的目标就是 30%（`CameraGoal.home`：只有回家不夹到 [0.7, 1.0]，那个范围只限制跟拍取景），到达判定对着你原来的视图，不会停在 70% 再丢掉它。画布挂载慢（切换后约 6 秒内）不会被当成你自己换了画布。**谁换的画布，在换的地方就说清楚**（`workstation/navOrigin.ts`，不再靠「近期有没有输入」去猜：浏览器的「返回」没有 pointer/键盘/滚轮事件，相机 0 秒切进子图、你 0.5 秒点面包屑返回，6 秒宽限过后输入窗口早就过期，都会漏）：你的导航入口——`App.tsx` 的 `go`（面包屑、返回按钮、快捷键、popstate）、点标签、打开画布——调 `userNav.note()`，相机立刻「已暂停」，不等它看到画布变了；相机自己切画布用 `byCamera(...)` 包住，不算你的；没有人说过话的画布变化是应用做的（智能体读、建子画布时应用会去打开它们），镜头不因此暂停，改在新出现的那张画布上接着跟（`canvas-moved`）。智能体读写没有标签的画布时，标签**安静地加入**（`workspace/model.ts` 的 `placeQuiet`：不成为任何组的当前标签、不在你的画布旁边分屏；`App.tsx` 的 `ensureCanvas`）；生命周期在 `workspace/quietTabs.ts`：**调用期间持有画布租约**（`agentBridge.ts` 的 `installBridge` 在整个请求前后 `ui.holdCanvas`，改图等素材一分钟也不会被关掉），租约放掉后空闲 8 秒才关；**你一动它就归你**（打开、聚焦、带到前面的那一刻 `own`，之后到期也不关，关的时候再查一次）；保存布局时**不写**还没归你的安静标签（`savedWorkspace` 的 `hidden`），刷新后不会留下孤儿。
  - **切画布时的视图**（`director.ts` 的 `switchView`）：回家给你原来的视图，否则是镜头对小人的取景，再否则是这张画布自己的适配视图**并夹在 [0.7, 1.0] 里**：实时永远不给整张大图（以前你暂停的同时镜头切画布，会走 `fitOf` 整图，缩放一帧从 1 掉到 0.3）。放一轮的总图（开头、汇总）不受此限。
  - **不留痕**：镜头自己带着切画布时，不保存项目布局（`replayQuiet.ts` 让 `persist.ts` 暂停 workspace 那一项的保存，切走的第一刻到回来之后才恢复）、不往浏览器历史里推记录（`replacingPush`，切画布的 push 换成 replace）、不弹「在子图里」的一次性提示、不弹「可能过时」（`NestedLayer` 用同一套静默，`replayQuiet.ts` 的 `staleVisible`）。你自己点进子图、换画布，照常保存、照常推历史。
- **动效**：换画布时两张画面交叉淡变（View Transition，约 320 ms）。减少动效：直接切，镜头直接到位，小人按 §5 的规则。

## 11. 追踪

追踪只跟回放走：「▶ 回放这一轮」放一轮，就只看这一轮这个 agent 走过的路：其余变淡，它去过的节点按顺序编号，路线沿它走过的桥和梯子画出来，子图入口标成传送点，子代理从派出到交回一条细虚线。这是 §9「Agent 树与追踪」里追踪的部分（状态 j），不做树面板。

| 文件 | 做什么 |
|---|---|
| `trace.ts` | 纯函数 `traceAt(run, t, ctx)`：它依次去过的地方（`stops`：节点或图外托盘，出发和到达的时刻，t 时到没到，在那里经子图入口进过哪张子图、去了里面哪些节点）；每两站之间那一趟的腿（`ways`：和行程同一条路线——同一对落脚点、同一张走图，桥和梯子就是从这些腿画出来的）；它的每个子代理从哪派出、去过哪、在哪交回（`subs`）。`walkedAt(way, t)`：这一趟到 t 走了多长（`trace.test.ts`） |
| `focus.ts` | `traced` 与 `focus.trace(id, turn?)`；`turn`（`TurnWindow`：轮号、起止，`end` 为 null = 还在跑）与 `traced` 同在这一个 store，`focus.escape()` 先关路线（也就放掉轮）；`traceTurn`、`hoverItem`、`panToItem` 见「按轮追踪」 |
| `Overlay.tsx` `workstation.css` | 追踪层（变淡、编号、路线、传送点、子代理虚线）和小人的动作行 |
| `../session/TrajectoryView.tsx` | 轨迹里派出的子代理一行（点它让镜头跟着它，§10）、当前行 |

- **进入与退出**：只有「▶ 回放这一轮」（对话里一轮头部的 ▶、轨迹里的 ▶）会开始追踪；播完路线和站点留在图上，用左上角「第 N 轮的路线 · 关闭」（Esc 也关）收起。单击小人或它的气泡只是选中它（出说话框、动作行），再点一次放开，不追踪；选中的小人气泡里只有两个按钮：「打开会话」（有自己会话的才有）和「跟随」（`bubbleActions.ts`）。点顶栏的 agent 小标签 = 打开它的会话。Esc 先关路线：画布上由 App 层的全局键，时间线里（泳道名、按钮、播放头上）由时间线自己；再按一次才清选中或回到实时。
- **变淡**：其余小人和它们的气泡、描边、牵绳、桥梯、「在读」虚线都降到 30% 不透明，点不到；追踪的 agent 和它各层的子代理不变，它的气泡总在。变淡立即生效，不等重建。
- **编号**：到访的节点左上角按顺序一个编号小圆（①②③…，再到同一个节点就接在上一个下面），走到那里（行程结束时；减少动效时是出发时）才实心，没到的空心淡色——回放时之后才到的那些就是这样。列的是 t 所在的这一段工作（空闲一分钟离场，下一段重新从 ① 算；子代理是它从派出到交回的这一趟），只列已经发生过的：实时时没有未来的站。
- **路线**：走过的路沿它走的桥和梯子画成一条细的主题紫线（就是行程的腿：台面上贴着节点上沿，过桥、上下梯子都在桥和梯子的位置，没另算一套）。正在走的那一趟跟着小人往前长，线头在它脚下（爬梯时它离梯子 4 个小人单位）；进入追踪时整条路线从 ① 起 650 ms 描出来。
- **传送点**：在某个节点经子图入口进过它的子图，第一个编号旁一个小药丸「第 1 站 · 在子图「应用入口、用户模块」里」（到 t 为止在那张子图里去过的节点，按顺序；太长就省略）。**药丸放在节点外面**（`stopPill.ts` 的 `pillSpot`：节点上沿外侧、右外侧、下沿外侧，取第一个既不碰别的节点/标签/别的药丸、也在窗内的；有小人站在这个节点上就跳过上沿；**也不碰别的浮层**：子图里有人时口里露出的头和「在子图 · 空闲」小字（`hatch.ts` 的 `peekBox`，纯几何，用 `PEEK_NOTE`、`PEEK_UP` 算）、入口胶囊（`entryCapsuleBox`）、说话框和气泡（从画面上量）；这些浮层的优先级是：在子图里的人 > 说话框 > 气泡 > 药丸，都放不下就不画药丸，只有编号，话在悬停里），不透明底（原来落在节点里盖住节点的字，未到的站整体半透明所以显得糊；现在只有已到的站画药丸），悬停这个站的号：「第 2 站：小人在这里进了子图「…」」（`stopEntryNote`，也是无障碍文字，悬停卡里同一句）。
- **子代理**：每个子代理从派出点经它去过的地方到交回点一条灰色细虚线（去和回各向一边弯，成梭形），出去那一段的正中放它的头像；交回之前线不回来。只有回执的 worker 不走，没有线。图外托盘上有站或经过时托盘显示出来。
- **拖动回放**：编号和路线跟着播放头变——到访顺序只算到 t，路线长到 t 时小人所在的地方。
- **界面**：路线在时其余小人变淡（没有时间线了，泳道和「追踪中」标签一起去掉）；子代理列在轨迹里派它的那一轮下面，点它让镜头跟着它（§10）。路线关闭后恢复。
- **结构与每帧**：编号、路线、虚线都随叠层 ≤ 4 Hz 的重建算；帧循环只让正在走的那一趟的线往前长（改一条 path）、切编号的实心、视图移动时挪标记。退出时整层 200 ms 淡出。
- **减少动效**：不描线，路线在出发时直接出现；标记和变淡照样是淡变。

### 按轮追踪：把一轮会话的工具调用画在图上

追踪的范围是**会话的某一轮**，不再是「t 所在的那一段工作」：站点、路线、子代理都只算这一轮里的。没有指定轮时默认就是它当前（或最近）的一轮（`latestTurnWindow`：从片段的轮号 `RunSeg.turn` 推）；从会话进入则是那一轮的 `[startedAt, endedAt]`，正在跑的一轮 `endedAt` 取「现在」，所以站点随新的工具调用增加（实时和回放都行；回放里 t 之后的站是空心的）。

- **入口（会话里）**：每一轮的头部——对话视图的 `第 N 轮` 行、轨迹视图的轮头——有一个「▶ 回放这一轮」（`session/TraceTurn.tsx`；这个会话还没出现在工位视图里时灰）。它追踪这一轮并用时间线自己的回放（`clock.play`，展开泳道后有 .25×–4× 的速度键，可以慢放）从这一轮开头放到结尾；这是你主动要求「放一遍」，所以这时镜头会动（见下面「放这一轮」），平时的实时画布照旧不动。**从指定步骤开始**：轨迹里每一行悬停出「▶」（`session/TrajectoryView.tsx` 的 `ds-rec-play`，「从这一步回放」），小人和镜头从这一步接着走（`session/playTurn.ts` → `plays.start(…, { from })`，起点夹在这一轮之内，`replayStart.ts` 的 `startAt`）。**点一行**：小人走到那一步——回放中就是时钟跳到这一步（暂停的留在暂停，放着的接着放，`jumpTo`），没在回放就从这一步开始并停在那里（「已暂停」，可继续、可关闭）。**路线显示时小人不消失**：被追踪的那个 agent 不再因为空闲超过一分钟而离开画布，站在它最后到的地方（`place.ts` 的 `Ctx.stay`，`Overlay` 传入被追踪的 run），路线关闭后恢复原来的规则。**播完之后路线和站点留在图上**：画布左上角是「第 N 轮的路线」和「关闭」（Esc 也关，`ReplayBar.tsx` 的 `TraceBar`），下面一行小图例「数字 = 这一轮先后到过的地方」（文字在 `traceText.ts`）。以前单独的「在图上看这一轮」（只画静态路线、平滑移到第一站）并进了这里：静态路线就是播完后留下的这一张。
- **放这一轮**（`replayMode.ts` `replayView.ts` `replayFollow.ts` `replayFit.ts` `replayCamera.ts` `replayDom.ts` `replayHistory.ts` `playCounts.ts` `ReplayBar.tsx` `ReplayMarks.tsx` `replay.css`）：
  - **镜头**：以被追踪的 agent 为中心跟拍，约 100%（[0.7, 1.0]）让节点文字清楚，小人、它正去的节点（在 `SHOT_REACH` 520 单位内才一起框，远的不缩小去装它）和气泡装不下就缩小；`replayFollow.ts` 的纯函数 `followView` 算目标视图和要不要动（死区：小人离画面中心不远时镜头不动），`director.ts` 的 `cameraStep` 让视图限速缓入缓出地过去（§17「镜头」）；扣掉顶部工具栏和横条占的高度（`replayDom.ts` 从 DOM 量）。开始先看一眼总图（约 1 秒，一次交叉淡变切过去）再推近；放到这一轮结束后切回总图，说汇总。
  - **进出子图**：小人在总图上走进子图入口、进了门（`portalPhase` 是 `behind`）的那一刻，主画布切进这张子图，和你点进子图一样（`nav.go`，面包屑和「返回」都在），切换是两张画面的交叉淡变（View Transition，约 320 ms；减少动效时直接切），落在小人附近的放大视角（`canvas/viewport.ts` 的 `firstView` 把视图交给新挂载的画布）；它出门就切回。`replayCamera.ts` 的 `cameraCanvas` 是纯函数。
  - **节点亮起**：这一轮改到的节点描紫框，右上角「+N」是到这一刻这一轮（含它派的子代理）在该节点写了几个文件（同一文件只算一次，`playCounts.ts`）；父节点在总图上显示子图里的合计；放完汇总浮标「这一轮改了 X 个节点、Y 个文件」放在最后写的节点上方的空处，避开连线标签，放不下就写在横条里（`replayFit.ts` 的 `placeBadge`）。
  - **小标注**（`ReplayBar`）：「回放中 · 第 N 轮」，没有按钮（控制都在右侧轨迹顶部，Esc 退出）；你手动拖动或缩放画布，镜头就停止跟拍，小标注旁出现「跟随小人」，点一下恢复（只在这一次放的过程里，不存）。
  - **放完**：汇总停几秒后自己结束，回到开始前的那张画布和视图，回放控制消失、右侧回到原来的视图，镜头回到 §10「默认跟随」。放的过程中：不保存项目布局（`persist.ts` 暂停 workspace 那一项的保存）、不往浏览器历史里推记录（切画布的 push 换成 replace）、不弹「在子图里」的一次性提示。
- **站点就是工具调用**（`Stop.calls`，`trace.ts` 的 `attachCalls`）：悬停编号，列出这一轮在这个节点上的调用，按时间：`Read server/app.py`、`Edit users.py`、`Bash pytest …`、`问你：…`；子代理写「派出 Codex：<任务>」和「Codex 交回」（派出那一行读不出是哪个子代理时，认领紧接着它派出的那个，不重复列）。一个文件的调用算在它那个节点最近的一站（走过去的那一步比调用晚一点开始也算），没有节点认领的文件算图外托盘那一站，项目外的路径（scratchpad、/tmp）和没有文件的调用（想、跑命令）算在小人当时站的那一站；思考不算调用。图外托盘也是一站。
- **点站点**：会话面板切到轨迹视图，展开这一轮，并**滚到这一站的第一步**，这一站**所有**有转录条目的调用行一起亮约 1.5 秒（`agora:step` 事件带 `itemId`（第一步）和 `itemIds`（`trace.ts` 的 `itemsOfStop`）；`SessionPane` 收 `itemId` 滚动，`TrajectoryView` 自己也收 `itemIds` 决定亮哪几行）；多轮时站点属于它那一轮（事件里带 `turn`），第 2 轮的站点跳到第 2 轮；这一站没有条目就滚到那一轮的头。
- **反过来**：轨迹视图里悬停一次工具调用（`RecordRow`），画布上它的节点亮一圈（和悬停站点是同一种虚线圈）、它所在那一站的编号高亮，移开恢复（`focus.hoverItem`）；**随时生效，不用先进入追踪**，站点和编号只在追踪中（回放中或回放后路线还留着）才有。那一步在子图里时亮的是主图上的子图入口节点（`geometry.locate` 把子图里的文件算在入口节点上）；没有落到任何节点的调用（`cd`、纯命令、项目外文件）不亮，也不报错。点它，画布平滑移到那个节点（`focus.panToItem`，一次）。行和站点靠同一个条目 id 对上：轨迹行的 id 就是工具调用的 `toolu_…`，站点里的调用带的 `itemId` 是同一串（真实会话 `s-7xzd5n5` 的 12 个调用逐个对过，`trace.test.ts`「a real session」）。
- **纯函数**（`trace.ts`）：`traceAt(run, t, ctx, known, win?)` 的 `win` 给出这一轮；`turnWindowOf`、`latestTurnWindow`、`spanOf`；「轨迹步骤 ↔ 站点」是 `stopForItem`（条目 → 哪一站，含子代理的）、`itemOfStop`（站 → 它的第一个有条目的调用）和 `itemsOfStop`（站 → 它所有有条目的调用，按时间）。测试在 `turnTrace.test.ts`。一轮落在更长的一段连续工作里时，这一轮的第一站是它开始时小人站的地方，不带前几轮的路。

## 12. 评论联动与进出子图

- **认出评论轮**：「交给 Agent」发出的消息第一行是「画布评论 #n（锚点：名字（id）、…）：」（`comments/handoff.ts`）。`lanes.ts` 的 `commentOf` 从这一轮的用户消息读出编号和锚点元素 id，这一轮的每个片段带上 `comment: { n, anchor }`（还在进行的轮次加 `open`）；只从转录推出，不另存状态，回放照样。`place.ts` 的 `commentSpans` 把它们连成一段（首个片段开始到最后一个结束）。

### 肘不翻侧（EL1）

BP1 在真实页面逐帧测出「走路时两只肘每 0.2 秒各翻一次，一帧 15–18 单位」。复核结果：**走路本身没有**（`scripts/pose-check.ts` 的长走扫描：3 种大小 × 2 种步频，每段 600+ 帧，肘一帧最多动 0.8 单位；真实浏览器里读 `figureNode` 画出来的上臂路径，同样最多 0.8）。翻侧的是别的三处（改前共 586 个 > 3 的肘位移，80 个 > 7，最大 18.7）：

1. **上梯子 / 下梯子时手抓梯档、放开**（走路到梯子的那一段，`climb` 在 0→1 之间）：手从垂下的位置到梯档是直线混合，穿过肩膀的位置。
2. **门的梯子**：身体就在梯子这条线上（`planDoor` 的根 x = 梯子 x），手抓的梯档离肩膀不到 1 单位，身体升过一档、手就从肩膀上方掠过肩膀下方。
3. **姿势切换**（举手 ↔ 放下、想 ↔ 空闲…）：手目标从一个位置跳到另一个，弹簧在 x、y 上各走各的，手走直线（弦），穿过肩膀附近。

根因（BP1 定位对了）：`ik()` 的肘方向 = `atan2(肩→手) ± A`，手从肩的一侧扫到另一侧，`atan2` 在一两帧内转近半圈，肘（离肩 9.36）跟着甩过去，10–19 单位。用「与手位置连续的弯曲方向」来解不掉：肘的两个候选对整个可达环带没有一个不断裂的选法（要么沿手方向转，要么在某条射线上断），任何不带状态的规则只是把断口移到别处。所以改的是手怎么走，不是 `ik`：

- **手绕着肩膀走弧线，不走弦**（`rig.ts` `solve` 的 `swing`）：弹簧不再跑在手目标的 x、y 上，而是跑在它对肩膀的角度和距离上（还是那四个弹簧，没有新状态；角度弹簧用 2.5 Hz，距离用原来的 3.2 Hz——弧比弦长，慢一点手的速度和原来一样）。距离只在两端之间变，角度均匀转，肘跟着均匀转，不会甩。
- **手抓梯档也走弧线**（`reach`）：角度以朝向为 0（正前方），从垂下的 +90° 到头顶梯档的 −90° 走「前面」，不从背后绕。
- **门的梯子，手比身体的线靠前 4 单位**（`Rungs.ahead`、`DOOR_AHEAD` = 4，和走路的梯子里「身体离梯子 GAP = 4」一样）：手抓的梯档从肩膀的前面掠过而不是从肩膀上掠过（距离 0.6 → 至少 4）。
- 伸懒腰的弧线 `ARC` 由 8 改成 10（手的路径现在由弧线 + 手势的目标一起决定，原来的余量不够）。

改后（`elbow-steps.png`，`track-before.txt`、`track-after.txt`，真实浏览器里读画出来的路径）：肘一帧位移最大 **6.2**（手在肩高抓梯档时肘平滑地转，不是翻侧），没有 > 7；走路 0.7。关掉的 80 个：梯子进出（18.2 → 4.9）、门（18.7 → 5.8）、举手放下（11.8 → 3.7）。`poseHealth.ts` 的 `elbowJumps`：任何一帧肘位移 > 7（走路 > 3）都算翻侧；`pose-check.ts` 默认报告里有，`poseHealth.test.ts` 也断言。没有动站姿、膝盖、骨长比例。

### 姿势分层、双手背后站姿、走爬速度连续（DR4）

用户看到的「猎奇」里，站姿本身（半蹲、两脚窄、手垂在肚子前）是最后一个没动的（§16 前面写的两处错帧修掉之后）。用户拍板：空闲站姿用设计板 G2 的第五种「双手背后」，姿势分层，走 ↔ 爬速度连续。真骨骼比例、两段 IK、capsule 绘制都没动。

**站姿**（`poses.ts` `STAND`、`standMotion`；`rig.ts` `poseTargets` 的 idle / unknown）：手在背后（手心的位置在躯干背边之外，近手 −6.4、远手 −7.1 单位，两手的深浅照旧：远侧手 `--fig-far`、画在躯干后面）、前倾 3°、髋高 +0.6（腿伸直，膝盖只有 3° 的弯，不超过腿够得着的 26.0）、两脚各 ±3.6（`RIG.stance` 由 2.6 改成 3.6，是落脚点，不是骨长，走路的落脚也跟着宽了）。自己的小动作：呼吸（髋上下 0.22 单位，4 秒一次）、重心微移（身体左右 0.45 单位，14 秒一个来回）、每九秒左右的一次转头（头转 1.8 单位、歪 5°，约一秒）；每个小人有自己的相位（`Springs.seed`）不会一起呼吸；减少动效时不动。所有「没在走、没在做手势」的地方都是它。

**姿势分层**（`poses.ts` 的 `layerStep`，纯函数；`rig.ts` `solve` 在手势之前调用）：底层 = 站 | 走 | 爬，上层 = 活动（读、写、执行、想、等你、派、交接）和手势。「在做什么」（姿态，或走路）一变，手、前倾、歪头、身体摇、髋高就从**上一帧屏幕上的样子**混到新的，0.28 秒（`BLEND_MS`）：
- 站 → 活动是起势（0.3 秒）：手先沿弧线到胸前抬起（`RAISE`），再去做事；
- 活动 → 站是收势（0.56 秒）：手到胸前拍一下（`CLAP`，近手进去再出来一次），再沿弧线回到背后；
- 其余（活动 ↔ 活动、走 ↔ 站、走 ↔ 活动）直接混合 0.28 秒；
- 混合半路又变了，从当前的样子接着混（不跳）；跳时间（拖动、后台回来）和减少动效直接复位；
- 手在混合里沿绕肩膀的弧线走（EL1 的规则：不掠过肩膀，肘不翻侧）；手势（`gestures.ts`）在这之上各自有权重，不受影响（伸懒腰的手绕脸前的弧 `ARC` 由 10 改成 13：手现在从背后出发）。
之后手的弹簧（角度 2.5 Hz、距离 3.2 Hz）还做小的平滑。

**走爬速度连续**（`rig.ts` `planTrip`、`natural`、`fitProfile`、`Profile`、`roundedRoot`）：见 §5「时长与步速」。走 ↔ 爬交界不再降到零：拐角速度 = 较慢那段步速的 0.6 倍，整趟最大加速度 1070 px/s²（改前 2300），一帧的速度变化不超过 0.0195 px/ms；各趟比改前短 1%–10%（3440 → 3072、3424 → 3072、2048 → 2016、4032 → 3728、2832 → 2656、6192 → 5648、672 → 672 ms），没有变慢。门的梯子本来就是一段匀速爬，没动（最大 1126 px/s²）。`trace.ts` 的 `walkedAt` 改用不圆拐角的原始路径（`rawRoot`），追踪线才不会因为身体圆了拐角而跳。

**体检加了什么**（`poseHealth.ts`、`scripts/pose-check.ts`，默认报告，有违规退出 1）：站姿的手在躯干背边之外（`behind`，不穿过身体画在前面）；站姿自己的运动幅度（髋 < 1.5、摇 < 2.5、头歪 < 10°）；活动的进出（起势、收势、活动之间，`layer` 场景，7 种活动 × 3 种下一步）一帧里关节跳不超过 5 单位；肘不翻侧照旧；每趟加速度 ≤ 1200 px/s² 且不在中间降到静止（`speeds()`）。全部姿势和过渡共 29580 帧，0 违规。

## 17. 导演层（DR2：小人；DR3：镜头）

用户要的是「丝滑，而不只是能看」：对话时不用自己找小人、小人不凭空出现在别处、镜头不乱冲。导演层是 `director.ts` 里的两个纯函数：`directorFrame(runs, now, delay, ctx)`（小人：延迟缓冲、出场位置、路径；实时和时间线回放都调它）和 `cameraStep(state, goal, {dt, now, pane})`（镜头：状态每帧由调用方带回）。`replayView.ts` 只把镜头的输出画到画布上。

### 改前（FL2 测出的根因，代码位置）

1. **对话后不提前跟**：`replayLive.ts` 的 `workOnDiagram`——只有「有文件在手、在路线上、进门」才算干活（`followsWhere(whereOf(...))`），思考、执行命令、托盘、等你都是 `think`/`tray`/`idle`，镜头 `asleep`（`replayView.ts` `frame` 里 `if (!live.awake()) return homeStep`）；无 seg 时 `lastWorkStart` 为 null，`< OPENED_AT` 也不跟。发话后到第一次读文件之间镜头不动。（DR3 已改：`workOnDiagram` 和 `awake` 门删掉，见「改后（镜头）」。）
2. **小人凭空出现在新位置（瞬移）**：`place.ts` `compute` 顶层 run 分支——一段工作的出场位置取「这段里第一个有位置的调用」`first ?? prev ?? OUTSIDE`。实时里第一个带路径的调用要等很久才到（真实 Claude 先想 6–24 秒），之前小人站在托盘，来了就直接站到新位置，没有走，也没有淡入淡出：真实 Claude 一段里 2522 个世界单位一帧内瞬移（`round-05/evidence/FL2`、`round-06/evidence/DR2`）。
3. **一轮没结束就睡 / 回家**：同 1 的 `awake` 门 + `liveCamera.ts` `liveStep`（`!working` 3 秒后回家；DR3 已改）；小人侧的「离场」是 `place.ts` 的 `IDLE_LEAVE_MS`（60 秒没有调用就淡出），一轮还在跑（想很久、等命令）也照样离场。
4. **延迟**：一个调用到达页面比它的日志时间晚 0.3–1.1 秒（日志 → 服务器 → 流），走路和淡入的起点却按日志时间算，到页面时动作已经过了一截。

### 改后（小人这一半）

- **延迟缓冲**（`director.ts`、`clock.ts` 的 `figureTime`）：实时，小人和气泡画的是 `now − LOOKAHEAD_MS`（600 ms）的世界；导演在 `now` 就知道「已到达、还没画出来的调用」（`known`：调用、它的地点），镜头一半用它提前决定。回放（时间线、拖动）`delay = 0`，未来全已知，同一个函数。图上的改动不延迟，只有小人的表演延迟。
- **出场位置不用未来**（`place.ts` `compute`）：一段工作开始时，第一个调用有位置就直接在那里；没有（先想）就站在上次站的地方（第一次是图外托盘；子图画布上是入口后面，不在场），第一个有位置的调用开始时走过去。小人在 t 的状态只取决于 t 之前开始的调用。
- **切镜**（`place.ts` `isCut`/`RunState.cut`，`director.ts` `FigureFrame.ghost`）：一段工作的**第一步**超过 `CUT_DISTANCE`（650）就不走：新位置淡入 `CUT_MS`（300 ms）、旧位置同时淡出（Overlay 为此多画一个淡出的小人 `~was`），两个透明度之和为 1、绝不同时全实；已经在干活之后节点之间的走动照旧（长也走，`REACH`/精简是另一回事）。减少动效不走也不切。
- **一轮没结束不回家**：`run.running` 且是最后一段工作时，不因几秒（几分钟）没有调用而淡出；一轮结束后仍是 60 秒离场。
- **到达时刻**（`runs/store.ts` `stampSeen`，`RunSeg.seen`，`place.ts` `startOf`）：一个调用第一次到达本页的时刻；实时的走路和切镜从那一刻起算（日志时间已经过去，切镜的 300 ms 会在画出来之前就走完），差 5 秒以上的（页面刚打开、日志早就在）当历史，按原时间。按会话持有（`seen`：会话不在 `agents.bindings` 里就释放，store 停了全部释放，还在的会话一条不丢，所以 `seen` 的补偿不会失效）。
- **测试**（`director.test.ts`）：（a）逐帧扫，帧间位移不超过速度上限，除了切镜；（b）切镜时新旧透明度之和为 1、没有一帧两处全实；（c）新一段工作的小人从上一位置出发；（d）延迟缓冲：`now` 到的事件 `now + D` 才画出，但 `now` 就已知；（e）时间倒流/暂停不出错；状态只取决于已开始的调用；迟到的调用照样淡入淡出。

### 智能体改图也是小人的活（FX3）

ACC1 发现真实 Claude 用 CLI 画图时整张图一次性冒出、小人整段站在托盘「思考」。原因：`agora canvas …` 是没有文件路径的 exec 调用，`place.ts` 的 `where()` 无位置。现在页面执行器（`agentBridge.ts` 的 `applyFromAgent`、`animFromAgent`、`childFromAgent`，只加发事件，行为不变）在改动**之前**发 `touches.record({session, canvas, at, until, nodes[{id,x,y}], say})`；`runs/store.ts` 每次重算时 `mergeTouches` 把它们并进 run；`geometry.ts` 把被改的节点（和通向它们的、开子图的节点）当作地点（没有文件认领它们），Overlay 在被改节点集变化时重建几何。设计取舍：用「节点路径」（`agora-node:<画布>/<节点>`）而不是新字段，这样 `where`/`locate`/`levelsOf`/`unmapped`/追踪都不用改（`playCounts` 要改：节点集合读 `edit.ids`，文件集合排除 `agora-node:` 路径，画布改动没有「+N」，摘要「X 个节点、Y 个文件」里 Y 不含它们）；`RunSeg.edit` 记这一站画了哪些节点。删掉/改掉的旧行为：评论的回合没有文件时不再直接出现在钉子上（`place.ts`），`comment.test.ts` 一条上锁测试随之改（从托盘走过去）。已知：每次改图后节点多了，站着的小人的工位可能重排，位置一帧跳一下（`docks.ts`，不在本单范围）。

**测得**（真实 Claude 临时项目「画出这个项目的架构」，同一脚本 `round-06/evidence/ACC1/scripts/acc-rec.mjs A`，改前 = ACC1 的 A 三次，改后 = `round-06/evidence/FX3/`）：改前小人整段站在托盘、被跟随的小人在窗格内占比 0.24–0.25、镜头因窗格自己换画布而「已暂停」；改后一次完整运行 14 站（57 个节点，2 次切镜）/ 23 站（102 个节点，4 次切镜），小人走到被改的节点、写、再走，走路速度中位数 131 px/s（设计的走速 130），窗格内占比 0.99–1.00，进出子图时镜头跟着换画布、没有被暂停。不在本单：空画布上第一次改图之前小人在图外（FX2a）、改图后站着的小人工位重排时一帧跳位（`docks.ts`）。

### 评审二（FX4）补的边界

- **被占区域**（`replayDom.ts` 的 `TOP` / `BOTTOM` / `FLOATS`、`occupiedFrom`，矩形集合见 §15「悬浮会话面板」）：顶上的工具栏、回放条、面包屑和「跟着」小胶囊（`.ws-follow-status`，挂在工具栏下面），底上的 Excalidraw 页脚，以及浮在窗格上的会话面板、评论列表、它们的胶囊，取景和镜头目标都把它们扣掉（以前只算顶上和底下的条，「跟着」胶囊也没算，图的上沿会压在它下面）。图比窗格高时，取景以小人为中心，图的上半在窗外是自然的，这里只保证小人和它的空间不被遮住。
- **悬停步骤的描边**（`canvas/highlightBoxes.ts`）：悬停会话里一步「改了画布」时，只给这一步改的**节点**画描边，不再给每一根箭头和每个标签画（一步画整张图时它们叠成一团紫）；只改了箭头的一步仍描箭头。这和工位视图的「有人在写」环无关（环只在小人当前所在的节点）。
- **气泡躲说话框**：「对 Claude Code 说…」框现在和工具栏一样进气泡的 `avoid`（`Overlay.tsx` 量 `.ws-talk` 的位置），气泡不再叠在它上面（框自己早就躲气泡）。
- **说话框始终完整在窗格里**（FX9）：框宽 232，窗格更窄时框跟着变窄（`talk.ts` 的 `talkWidth`，最窄 120），再放进窗格内（`placeTalk`）；框里的提示字（「对 Claude Code · 画出这个项目的架构…（回车发送）」）按框宽在**字边界**截断加 …（`fitEllipsis`；输入框有焦点时浏览器不给 placeholder 加省略号，会把最后一个字切掉半个，所以自己截），悬停（`title`）看全文。
- **所有拖动共用一个 `dragGuard`**（`app/dragGuard.ts`，组件里用 `useDragGuard()`）：按下拖动柄时，页面 `user-select: none` 并清掉已有选区、拒绝 `selectstart`/`dragstart`、指针归拖动柄（pointer capture，下面的画布收不到）、按下时 `preventDefault`、页面光标换成这次拖动的（`col-resize`/`grabbing`）；松手、取消、丢指针、窗口失焦、Esc、组件卸载任何一种都原样恢复，同时几个拖动按计数，最后一个结束才恢复。用了它的拖动：窗格分隔条（`Workspace.tsx` 的 `onSashDown`）、标签拖动重排、评论面板标题条、轨迹时间轴的范围。别的地方要拖（比如悬浮会话面板）：`const guard = useDragGuard(); onPointerDown={(e) => guard(e, { cursor: "grabbing", onEnd: (why) => … })}`，`why` 是 `up|cancel|lost|blur|escape|manual`，非 `up` 时把拖动放弃。
- **改图积压**（`runs/touch.ts` `mergeTouches`）：落后超过 `BACKLOG_MS` 时，新的一次改图**取代**同一张画布上还排着没开始的旧站（只显示最后一个位置），队列不再随每次更新增长；10 秒内对同一节点更新 100 次，最后一站在最后一次更新后约 8 秒内结束（以前落后 132 秒，`isWorking` 一直为真）。
- **派给已有会话的改图**（`runs/store.ts` `withTouches`）：`tree.children` 里 `dispatchSession` 指向已绑定会话的子 run，递归并入那个会话的改图，祖先的 `lastAt` 跟着更新，再做顶层去重。
- **被删掉的子图节点不是地点**（`geometry.ts`）：进门的路要目标画布**和**目标节点都还在；`doorTo` 只看还在的被改节点，`locate` 和 `levelsOf` 一个规则；节点已被删掉时小人留在原地。
