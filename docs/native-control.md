# 原生会话控制契约

本文描述顺序、权限、事实归属与接缝证据。字段和 schema 只在 [`native_protocol.py`](../native_protocol.py) 定义；非 Python 消费者读取 `python -m native_protocol` 的导出。产品目标见[工作台计划](canvas-workbench-plan.md)，验收状态见 [Issue #18](https://github.com/arvakme/agora/issues/18)。

**契约未冻结。** Codex 的独立原生控制实验已通过审查，Claude 的完整接收与终态仍未验收；当前契约也尚未定义中断终态。原生接缝实证不等于 Pi 或产品集成通过，不得据此启动依赖接口冻结的工单。

## 1. 事实与授权

Agora/Postgres 拥有房间、成员、请求、公开结果与 Master 验收。授权来自已认证连接及服务端对成员和 Computer 的绑定；请求是否仍有效，必须在提交结果时由后端校验。

宿主只拥有本机会话、输入权与尚未确认的传输记录。各 CLI 拥有自己的原生对话记录。所有 ID、序号、工作目录和 tmux target 都是地址，不是凭据；宿主也能生成一个地址，不能用字段非空或序号递增证明授权。

## 2. 投递、关联与结果

请求先在 Agora 持久化，再发送“有更新”的通知；断线后按序号补读。宿主在串行输入锁内检查输入权、暂停、权限等待和在途请求，再持久化注入窗口，最后投递。注入窗口内失去确认的状态是不确定，不承诺模型副作用 exactly-once。

三种事实必须分开：CLI 接受输入、CLI 完成回合、Master 验收结果。tmux 返回成功、终端安静或模型打印 done 都不能代替原生回执。原生 RPC 分配了回合 ID，也不自动证明输入已经持久化。

事件必须匹配本部署登记的原生会话；绑定后还必须匹配原生回合。CLI 内部线程不能冒充工作结果。关联标记只帮助找到那条输入，最终绑定仍须由原生载荷确认。

结果先于绑定到达时，保留结果而不提前确认。绑定后用原事件 ID 合并；返回的 effect 表达合并后的完成或迟到结果，不仅表示“绑定成功”。重复事件只补确认，已落定的回合不被后续信号翻转。进程退出本身不能证明回合完成或失败。

## 3. 撤销与物理执行

撤销是请求权威的不可逆决定，不能被宿主重启、进程退出或迟到完成撤回。已撤销请求不能打开注入窗口，也不能重投；已经投出的模型回合则可能继续执行。

迟到结果保留为物理事实，但不作为有效任务结果发布。命令已发送不等于原生回合已停止；只有可归属的终态才能释放在途回合。停止指令与自然完成发生竞态时，也不能复活已撤销请求。

## 4. 输入权与 attach

默认只读 attach，连接同一个真实 TUI，不启动第二个推理进程。人工接管排他且不隐式取消正在执行的回合。detach 不是归还；控制连接中断后保持暂停。发现未纳管可写客户端时暂停自动投递，不强踢用户。锁与交接由宿主实现，提示词和 tmux 多客户端机制不是安全沙箱。

tmux 3.7b 的按键必须显式指向本部署自有的可写客户端（`send-keys -c`），不依赖随 attach 变化的当前客户端。文本使用 bracketed paste，与提交或停止键分开发送。零模型字节接收器已验证输入分帧、只读输入被拒绝及只读客户端 detach 后进程继续；这些传输事实不能代替 Claude 的原生输入接收与终态。原生 RPC 输入不受终端客户端选择影响。

## 5. CLI 接缝与验证状态

目标架构中，Pi 的原生 TUI 扩展只调用宿主，不另建 Worker 池。开发团队能够使用某个 CLI，不代表产品已自动纳管它。

Claude Code 2.1.268 已核对原生 `SessionStart`、PID、会话标识与进程起点。完整输入接收、自然完成、中断及接管仍未验收；现有实验的投递和观测缺陷不能作为 CLI 不支持这些能力的证据。

Codex 0.153.4 的工作现场由真正的 TUI 创建线程，控制端可从原生 `ThreadStarted` 得到身份，不需要为获取身份跑额外引导回合。使用自有回环 app-server，不接用户已有守护进程；WebSocket 客户端需关闭压缩协商。公网 remote-control 必须关闭，不能因此修改用户全局设置。

Codex 的 `turn/start` 可投递输入并返回原生回合 ID。创建线程的广播不等于订阅回合事件；空线程即使已经加载，`thread/resume` 仍可能因尚无 canonical rollout 而失败。

Codex 已在同一真实 TUI 中核对正常与中断两回合：原生 `UserMessage` 精确对应请求的客户端标识与回合 ID，终态分别为 `task_complete` 和 `turn_aborted`。正常回答同时出现在该 TUI；两次终态后 PID 与只读客户端属性不变。中断记录可早于中断 RPC 的 ACK，不能以 ACK 顺序裁定结果。用量有原生记录才入账，缺失代表未知；原生回合数不是供应商 HTTP 请求数或费用。

`thread/status/changed` 的 idle 通知先于终态写入屏障；paginated 查询还可能将未落定的 InProgress 归一成 Interrupted。因此“收到 idle 后查询一次”不能可靠裁定结果。已验证的 macOS 接缝使用文件变更事件，从完整记录游标补读确切原生 JSONL；父目录尚未建立时，沿该路径的已存在祖先订阅，逐层先注册再补读，不遍历其他会话内容。合成夹具覆盖半行、重订阅和目录创建；跨平台与消费者的持久事务仍未验证。

TUI 未命名时会额外调用模型生成标题。先用 `thread/name/set` 命名并等待该 TUI 确认，已验证的两回合未产生额外命名线程。内部线程事件不得进入工作结果，其模型调用也不能忽略记账。

## 6. 冻结与后续实现

共享文件只有一个写者，以 Issue 的实际认领为准。冻结仍需补齐两种非 Pi CLI 的真实控制证据，并验证注入窗口失败、取消后提交、记录补读与输入权交接；代码测试不能替代这些原生行为。

宿主、授权与持久投递、部署、Pi 集成的分工分别以 #19–22 为准。替换旧执行路径时，由集成工单检查所有消费者并删除失效执行入口、测试和文档，不保留另一套推理循环或旧引擎回退。
